# 問題構成案（ステージ 1〜100 タイトル草案）

**作成: 2026-08-10 / ステータス: 草案（タイトルのみ）**

## 設計方針

- **到達目標:** 未経験〜入社3年目相当。「実務で最低限知っている必要があるもの」に絞る
- **形式:** 全問「他人のコードを読んで説明する」形式（Ferret のコアバリュー）。書かせる問題は作らない
- **配分:** JS 80問（ステージ1〜80） / TS 20問（ステージ81〜100）
- **除外:** React・Next.js（別カリキュラムとして後日作成）、DOM操作/Todoアプリ系（優先度低と判断）
- **1ステージ = 1問** の想定（要検討 → 末尾「未決の論点」参照）
- **章立ての軸:** 「実務でコードを読むときに詰まる場面」順に再編したもの。市販教材の目次順ではなく、Ferret 独自の読解スキル軸で構成する

## 出典と権利の扱い

### 何を参照し、何を参照していないか

本構成案で外部資料から取り入れたのは、**JavaScript / TypeScript という言語が備える機能の名称と、その一般的な学習順序**のみである。これらは言語仕様そのものに由来する事実であり、特定の著作物に固有の表現ではない（`const` / `Promise` / `keyof` といった名称は ECMAScript 仕様および TypeScript 公式仕様上の用語）。

参照資料の**本文・解説文・図表・サンプルコードは一切取り込んでいない**。以下は網羅性の確認（「実務で必要なトピックを取りこぼしていないか」のチェックリスト）としてのみ用いた。

| 資料 | 本案での使い方 |
|---|---|
| JavaScript Primer（jsprimer.net） | JS のトピック網羅性の確認 |
| サバイバルTypeScript（typescriptbook.jp） | TS のトピック網羅性の確認 |
| 各種入門記事 | 入門帯（ステージ1〜16）の粒度感の確認 |

章立ての順序は上記いずれとも一致しない。例えば jsprimer は「関数 → 条件分岐 → ループ」「プロトタイプ → 配列」の順だが、本案は「条件分岐 → ループ → 関数」「配列 → クラス/プロトタイプ」の順とし、読解の難易度勾配を優先して再編している。

### 参照資料のライセンス実態（2026-08-10 確認）

| 資料 | 文章 | コード |
|---|---|---|
| JavaScript Primer | CC BY 4.0（出典表示で商用利用・改変可） | MIT |
| サバイバルTypeScript | CC BY-SA 4.0（表示 + **継承**） | MIT |

**注意:** サバイバルTypeScript の文章は **ShareAlike（継承）** 条件付き。文章を翻案した場合、その派生物も同一ライセンスでの公開義務が生じ、商用クローズドな問題コンテンツとは両立しない。したがって **TS 編は同資料の文章を参照せず、トピック名のみを扱う**方針とする。

### 問題作成時の遵守ルール（コンテンツ制作フェーズで必須）

1. **コード例は全て自作する。** 既存教材のサンプルコードをそのまま／変数名だけ変えて使うことを禁止する
2. **解説文・模範解答の文言を流用しない。** 参照資料を開いたまま執筆しない（閉じてから自分の言葉で書く）
3. **一次情報は言語仕様と MDN に取る。** 仕様上の挙動を確認する際は、教材ではなく ECMAScript 仕様 / TypeScript 公式ドキュメントを当たる
4. **題材は実務由来にする。** ユーザー登録処理、API レスポンス整形、集計バッチなど、業務で実際に読むコードを自前で構成する。教材向けの人工的な例（`foo` / `bar`、動物クラスの継承など）は既存教材と衝突しやすいので避ける
5. **万一の引用が生じる場合は出典を明記する。** CC BY 4.0 の資料（jsprimer）は出典表示により利用可能だが、原則として上記1〜4により引用自体を発生させない

## 未決の論点

1. **「主要ライブラリ対応」が現状ほぼ未カバー**
   80問のうちライブラリらしい題材は 77〜80 の4問のみ。zod / date-fns / axios / lodash / Vitest あたりを扱うなら +8〜10問が必要。

2. **1ステージ1問だと定着が弱い可能性**
   1ステージ = 3問（易・標準・応用）にすると総問題数 300問。「気づいたら実力がついていた」を狙うなら反復は要る。

3. **総量が3年目到達には足りない疑い**
   特に非同期(10問)・配列(12問)は実務ペインの中心。ここは各 +5 問の余地。TS 20問も薄く、strict な現場コードを読むには 30〜35 問欲しい。

4. **入門帯（DOM 操作）の扱い**
   本案では DOM 操作系を全て除外している。React を別カリキュラムとするなら素の DOM は不要という判断も成立するが、確定が必要。

5. **問題文・コード例の著作権チェック工程**
   80〜100問を作り切った後、公開前に「既存教材のサンプルコードと偶然一致していないか」を機械的に照合する工程を挟むか。（一致リスクが高いのは `fizzBuzz` など定番題材のみと想定）
