## 未移植（データ・機能が足りないもの）

### 1. フィードバックの2枠表示（よかったところ / つぎの一歩）

- **モック:** `result-desktop-light.html` は praise / next_focus を別々の枠で表示
- **状態:** ✅ **移植済み（2026-08-18・`tasks/E2`）。** `user_attempts` に `ai_praise` / `ai_next_focus` を
  追加し、モックの `.fb-tag`（ブランド色のピル）に合わせた2ブロックで表示している
- **モックとの違い:** **片方が空の回はその枠を出さない。** 禁止語で差し替えた先のテンプレートが
  空になる帯域があるため（80点以上に「つぎの一歩」は無く、55点未満かつ `core=none` に「よかったところ」は無い）
- **過去の行:** 保存済みの文章を機械的に2つへ戻した（`supabase/backfill/20260818224500_split_feedback.mjs`）。
  分ける前に採点した2件だけ、つなげた文章を1枠で表示する経路が残っている
- 採点ロジック・grader_version は変更していない

### 2. XP バー・「+10 XP」表示

- **モック:** リザルトに XP バー、ステージのポップオーバーに「クリアで +10 XP」
- **状態:** ✅ **移植済み（2026-08-18・`tasks/E3`）。** リザルトの XP バーと「+N XP」、
  ステージのポップオーバーの「クリアで +10 XP」がどちらも実データで動いている
- **モックとの違い:** `users.xp` への加算はしない。`user_attempts` の**最高点**から毎回導出する
  （`lib/progress/level.ts`）。クリア +10 / パーフェクト +15 なので、
  ポップオーバーの「+10 XP」はクリア帯の額を指す
- **レベルをまたぐ回:** バーを右端まで満たしてから空に戻し、新しいレベルのぶんを満たす。
  前の位置から直接動かすと（90% → 0%）増えたのに**縮んで**見える

### 5. Shiki シンタックスハイライト ── ✅ **移植済み（2026-08-18・`tasks/E5`）**

- **既製テーマ `gruvbox-dark-hard` をそのまま使う**（オーナー判断）。カスタムテーマは作らなかった。
  既製40種をモックの `--code-*` 6色と機械的に突き合わせ、**色差がいちばん小さいもの**を選んでいる
  （2番手の material-theme-darker とは色差 26.7 対 37.9。手順は `tasked/E5-コードの色付け.md`）
- `--color-code-bg` / `--color-code-ink` は**テーマの背景・地の文に合わせて置き換えた**
  （`#211b12` → `#1d2021` / `#ece2cd` → `#ebdbb2`）。色付きの `<pre>` は自分の背景色を持って
  出てくるので、揃えないと見出しの帯と本文で段差に見える。**ズレを検知する単体テストがある**（U-604）
- 色付けは `lib/code/highlight.ts`。問題画面はサーバーコンポーネントのままで、
  **ブラウザ側の配布物には Shiki が1バイトも乗っていない**（`.next/static` に文法もテーマも無いことを実測）
- **実行結果（`context`）のパネルには色を付けない。** エラー文はコードではないので、
  文法として色分けするとキーワードに見える単語だけが光ってかえって読みにくい

### 6. 影響型（スタックトレース等）の2パネル表示

- **必要な決定:** code 内の区切り記法にするか、nullable な `context` カラムを足すか。

- 命名型の「中身を伏せる」表現は code 本文に `/* …… */` を書けば済むので変更不要

### 8. モバイルレイアウト ── ✅ **対応済み（2026-08-19・`tasks/E8`）**

- 3カラムは lg（1024px）以上のみ。lg 未満はサイドバー・右レールを消して簡易ヘッダーで代用している。
  **この構造は変えていない。** 幅375px で実測したところ、簡易ヘッダーの側で実際に壊れていたのは2か所だけだった
  （横に溢れている画面はゼロ、ログアウトも簡易ヘッダーで届いていた）
- **`stages-mock.html` のモバイル版レイアウトは採用していない。** あのモックは
  上部バー＋ボトムナビ＋430px のアプリ枠という別構造で、いまの簡易ヘッダー方式を
  作り替えることになる。実測で壊れていた2か所を直すほうが影響範囲がはるかに小さい
- 直したのは ① マップの「スタート」吹き出しが1つ上の行のラベルに重なる
  （`ROW_H` を lg 未満だけ 180→224。**SVG の `y1`/`y2` に入る値なので CSS では切り替えられない**）
  ② 問題画面の下の固定バー（lg 未満では固定をやめて回答欄の真下へ。仮想キーボード対策）
  → 詳細は `tasked/E8-スマホ対応.md` の作業記録

### 9. マップ上のパーフェクト演出 ── ✅ **移植済み（2026-08-17・`tasks/E7`）**

- 案A（金の縁取り）で実装。クリア済みの丸の外側に `ring-3 ring-[#d98a06] ring-offset-2` を一重足すだけで、

## 運用メモ

- 章の定数マップ（`lib/stages/chapters.ts`）は問題構成案の章立てが変わったら更新が必要。
  章を跨ぐ問題の差し替え運用が始まったら DB カラム化を再検討
