# デザイン移植の残タスク

**2026-08-17 時点。** `design/` のモックのうち、アプリ側（`app/` / `components/`）へ移植済みのものと、
データ・機能が足りず移植できなかったものの整理。

## 移植済み

- デザイントークン（`app/globals.css` の `@theme`）とフォント（M PLUS Rounded 1c / JetBrains Mono、`app/layout.tsx`）
- タイトル / ログイン / 新規登録（ロジック無変更、見た目のみ差し替え）
- ステージ選択: 3カラムレイアウト（`AppSidebar` + マップ + 右レール）、章バナー（sticky・スクロール追従）、
  章区切り帯、ノードのポップオーバー、「現在地へ」FAB、起動時の現在地スクロール、マスコット・スタート吹き出し
- 章データは `lib/stages/chapters.ts` の定数マップ（出典: ideas/問題構成案.md v3）。DB カラムにはしていない
- 問題画面: ×（中断）、reading_type チップ、ダークコードパネル、下部固定フッター（OpenAI 注記 + 回答ボタン）、
  採点待ちのマスコット演出
- リザルト: 統計チップ3枚 + カウントアップ、紙吹雪（クリア時のみ）、合否で主ボタンを出し分け

## 未移植（データ・機能が足りないもの）

### 1. フィードバックの2枠表示（よかったところ / つぎの一歩）

- **モック:** `result-desktop-light.html` は praise / next_focus を別々の枠で表示
- **足りないもの:** `lib/ai/scorer.ts:169` が `[praise.text, next.text].join(" ")` で
  **1本の文字列に潰してから** `user_attempts.ai_feedback` に保存している。分離して復元する手段がない
- **必要な変更:** 保存形式の変更（例: `ai_praise` / `ai_next_focus` カラム追加、または JSONB 化）。
  採点ロジック自体は変わらないので grader_version の変更は不要
- **当面の挙動:** リザルトは `ai_feedback` を1枠で表示（`ResultView.tsx` にコメントあり）

### 2. XP バー・「+10 XP」表示

- **モック:** リザルトに XP バー、ステージのポップオーバーに「クリアで +10 XP」
- **足りないもの:** `users.xp` カラムは存在するが**加算するロジックがどこにもない**（TASKS.md の将来枠）
- **必要な変更:** 採点 API のクリア時に XP を加算する処理 + レベル閾値の設計
- **当面の挙動:** XP 関連の表示はすべて出していない（嘘の数字を出さない）

### 3. 「きょうの AI 採点」ウィジェット（右レール）

- **モック:** Free の1日3問の残数を肉球3つで表示
- **足りないもの:** レート制限そのものが未実装（TASKS.md「課金開始前に必須」）。
  集計クエリ自体は `ideas/db仕様.md`「レート制限のクエリ」に完成品がある
- **必要な変更:** レート制限の実装と同時にウィジェットを追加する。
  制限の強制なしで残数だけ出すと「0になっても採点できる」矛盾表示になるため、先行実装はしない

### 4. Pro プロモカードのボタン

- Stripe 未実装のため、右レールの「Pro をみる」は**押せないボタン（準備中）**にしてある。
  Checkout 実装時に有効化する

### 5. Shiki シンタックスハイライト

- コードパネルは暖色ダークの `<pre>` 素通し（モックは手動ハイライトだった）。
  `shiki` は未インストール。導入時はモックの配色（`--color-code-*` トークン）に合わせた
  カスタムテーマを作る。問題画面はサーバーコンポーネントなので SSR ハイライトにできる

### 6. 影響型（スタックトレース等）の2パネル表示

- **モック:** `problem-samples-desktop-light.html` の影響型はコード + 実行ログの2パネル
- **足りないもの:** `problems.code` は TEXT 1本で、ログを別パネルにする構造がない
- **必要な決定:** code 内の区切り記法にするか、nullable な `context` カラムを足すか。
  **6問検証で影響型（ステージ59）を作る前に決める必要がある**
- 命名型の「中身を伏せる」表現は code 本文に `/* …… */` を書けば済むので変更不要

### 7. ふりかえり / せってい画面

- サイドバーに「準備中」として置いてある。ふりかえりは `user_attempts.axes` に
  4観点の判定と引用が入っているので材料は揃っている（TASKS.md 画面の残り）

### 8. モバイルレイアウト

- 3カラムは lg（1024px）以上のみ。lg 未満はサイドバー・右レールを消して簡易ヘッダーで代用している。
  スマホ本対応（`stages-mock.html` のモバイル版レイアウト）は別途

### 9. マップ上のパーフェクト演出

- リザルトには 80点以上のパーフェクト表示があるが、マップのノードは cleared / current / locked の3状態のみ。
  `loadProgress` が bestScores を返しているので、パーフェクトノード（例: 金の縁取り）は
  `PERFECT_THRESHOLD` との比較を足すだけで出せる。演出を決めてから

## 運用メモ

- 章の定数マップ（`lib/stages/chapters.ts`）は問題構成案の章立てが変わったら更新が必要。
  章を跨ぐ問題の差し替え運用が始まったら DB カラム化を再検討
- ダークテーマを出す場合は `design/stages-desktop-dark.html` の `:root` トークンを
  `globals.css` に `[data-theme="dark"]` として足せば切り替えられる設計にしてある
