# 積み上げ型学習アプリの定番機能と Ferret の対応状況

**2026-08-17 作成。** Duolingo / Progate 系の「この種のアプリなら普通ある」機能を、
実害と優先度で仕分けたもの。ステータス列は Ferret での現状。

## A. すぐ入れる価値があるもの（安くて実害を防ぐ）

| 機能 | 実害 / 価値 | ステータス |
|---|---|---|
| 回答の下書き保持 | 長文を打った状態で×やリロードで**回答が全消失**する。消失事故は解約級の体験 | ✅ **実装済み（2026-08-17）** localStorage に自動保存・復元。送信成功で破棄 |
| 採点への異議申し立て | 自由記述採点では「正しいのに低得点」が構造的に必ず起きる（ideas/採点システム_残課題.md）。押された回答は**ゴールデンセットの材料**として貯まる | ✅ **実装済み（2026-08-17）** リザルト画面のボタン + `problem_feedback` テーブル + `/api/feedback` |
| 問題の誤り報告 | 1人で100問作る体制ではユーザーが最強のQA | ✅ **実装済み（2026-08-17）** 異議申し立てと同じ仕組みに相乗り（kind で区別） |
| ストリーク（連続日数）🔥 | このジャンルの継続率装置の本体。UI概要にも将来候補として記載 | ✅ **実装済み（2026-08-17）** `user_attempts.created_at` から導出（新テーブル不要）。右レールに表示 |

## B. 公開前に必須（法務・信頼系）

| 機能 | 実害 / 価値 | 足りないもの |
|---|---|---|
| 利用規約・プライバシーポリシー | 回答を OpenAI に送る旨の注記（§9.5）の根拠になる文書。タイトル / ログインのフッターが定位置 | ✅ **画面と下書きは完成（2026-08-18・C2）。** `/terms` `/privacy`、フッターは予定どおりの定位置。**残っているのは法務レビューのみ**（`tasked/C2-法務文書をそろえる.md` の作業記録に確認点5つ。公開ゲートは `残タスク.md` §C-4） |
| 特定商取引法に基づく表記 | 課金開始時に必須 | Stripe 導入と同時 |
| せっていの中身（メール変更・パスワード変更・退会） | 退会（アカウント削除）は個人情報を預かる以上、公開前に必要 | パスワード変更は `auth.updateUser` で安い。メール変更は確認メール送信が必要で **Resend 切替（TASKS.md リリース前必須）が先**。退会は admin API のサーバールートが必要 |
| 解約導線 | 「解約しにくい」という評判は致命傷 | Stripe 導入と同時（Customer Portal が最安） |

## C. MVP後の定番（リテンション系）

| 機能 | メモ |
|---|---|
| デイリー目標 + リマインダーメール | Resend 導入後。ストリークとセットで効く |
| 診断テスト（開始位置スキップ） | 問題構成案の未決論点5。3年目に第1章から7問やらせると離脱する |
| 効果音 + ミュート切替 | Duolingo の気持ちよさの相当部分は SE。せってい画面ができてから |
| ダークテーマ切替 | トークンは `design/stages-desktop-dark.html` で設計済み。`[data-theme]` で差し替えるだけの構造にしてある |
| リザルトのシェアボタン | 成長導線の定番。認定証と相性がよい |
| マップのパーフェクト演出 | `loadProgress` が bestScores を返しているので `PERFECT_THRESHOLD` 比較を足すだけ（design/移植残タスク.md §9） |

## D. Ferret にはあえて入れないもの

| 機能 | 入れない理由 |
|---|---|
| ハート / ライフ制 | 「AI採点の残数」が既に同じ経済の役。二重の制限は理不尽さだけ増える |
| リーグ / リーダーボード | インフラが重い上に、他人と比べて下位に置く仕組みは**ネガティブワード禁止・装備獲得型の方針と根本的に相性が悪い** |
| フレンド機能 | ターゲット（新人が一人で鍛える）に対して過剰 |

## 実装メモ（A で追加したもの）

- **下書き保持:** `ProblemForm` が `ferret:draft:{problemId}` キーで localStorage に保存。
  復元時は「前回の下書きを復元しました」を文字数カウンタの位置に表示。送信成功時に破棄
- **異議申し立て / 誤り報告:**
  - `supabase/migrations/20260817100000_problem_feedback.sql` — `problem_feedback` テーブル。
    RLS 有効・ポリシーなし（読み書きとも service_role 経由のみ）。
    `unique (user_id, problem_id, kind)` が連打スパムの安い歯止め
  - `app/api/feedback/route.ts` — 認証・CSRF・Content-Type・本文サイズは `/api/score` と同じ守り。
    attempt_id は本人の行かを RLS 経由で確認してから紐付ける
  - **理由の記入は必須（10〜500文字）。** ボタン1つで送れると「意地悪の連打」と
    「本当に採点がおかしい報告」を区別できないため、書く手間を本気度のフィルタにしている
    （2026-08-17 にワンクリック式からフォーム式へ変更）。しきい値は `lib/feedback.ts`
  - 同じ問題への同種の再送は「書き直し」として理由を上書きする（黙って捨てない）
- **ストリーク:** `lib/progress/streak.ts`（純粋関数・単体テスト付き）。
  JST の日付で数え、**きょう未回答でも昨日まで続いていれば維持**（きょう解けば +1）。
  0日のときは「きょう解くと 1日目」表示にして、0 を罰に見せない
