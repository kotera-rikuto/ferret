## なぜ差し替えたか

`tasks/A3` の実測（2026-08-26）:

- **難度が階段になっていなかった** ── 旧2問目が難度3（最難関クラス）で、2問目で急に上がっていた

  旧2・5問目はコメントや意図と実装の食い違い。**1問目で「Ferret は引っかけを探すゲーム」と学習させてしまう**

  10件中クリア3件・矛盾検出5件。矛盾検出は30点上限なので、**1問目で0点相当の体験になりやすい**

**軸は「難度を下げる」ではなく「引っかけを外す」。** ターゲットは新人〜3年目で、完全初心者ではない。

## 3問が満たしている条件

| | |
|---|---|
| 出力がある | 「何も出力されない」「エラーで止まる」を答えにしない |
| 読めば追える | 暗黙の型変換・コメントとの食い違い・`==` のワナを出さない |

## ⚠️ `core_reject` の作り方でひとつ判断を変えた

起票時のメモは `core_reject` の材料として「**変数の値を1つ前の状態で答える**」を挙げていた。
**この3問では採らなかった。**

トレース型の `depth` は「具体的な値・回数・順序に踏み込んでいる」ことを求めるので、
**途中の値に触れることが `depth` の満たし条件そのもの**になる。例えばステージ1の `depth` は
「3600 という途中の値に触れている」だが、同じ 3600 を `core_reject` に
「3600 が出力されると読んでいる」として置くと、**正しく途中の値を書いた回答で
矛盾 veto が誤爆しうる**（引用付きなら30点上限、申告だけでも40点上限＝クリア閾値55に届かない）。

チュートリアルで最も避けたいのは0点体験なので、代わりに次の2つを材料にした。

1. **反転**（足す ↔ 引く、片方の値 ↔ もう片方の値）── ガイドが最優先と書いている材料
2. **読み落とし**（掛け算を飛ばす、一時変数の役目を読み落とす、エラーになると思う）

どちらも**引っかけを足さずに作れる**。「素直な問題ほど `core_reject` が書きにくい」への答えがこれ。

## ステージ 1 ─ 注文金額の計算を1行ずつ追う

| 項目 | 値 |
|---|---|
| order | 1 |
| language | js |
| difficulty | **1** |
| reading_type | トレース |
| 収束性 | 一意 |

### code

```js
function subtotal(unitPrice, count) {
  let total = unitPrice * count;
  const shipping = 500;
  total = total + shipping;
  return total;
}

console.log(subtotal(1200, 3));
```

### question

このコードを実行すると何が出力されますか。その数になるまでの過程も説明してください。

### 出力（`run-code.mjs` で実行確認）

```
4100
```

### 設計メモ

- **1問目に置く問題なので、分岐もループも関数の入れ子も無い直線のコードにした。**
  `let` と `const` は旧1問目と同じ題材だが、**`const` への再代入をやめて「変わらない値」としてだけ置いている。**
  エラーで止まらないので、答えは必ず数になる
- `core` は「4100 が出力される」の1要素。`ground` は足している行、`depth` は途中の 3600。
  **`core` だけを満たす一文（「4100 が出力されます」）では `ground` も `depth` も none になる**ので、
  ガイドの「`depth` は `core` から独立させる」を満たしている
- `core_reject` は 1700（`count` を掛け忘れ）と 3100（足すのを引くと取り違え）。
  **どちらも正しい回答には現れない値**なので、誤爆しない

```js
let primaryOwner = "田中";
let backupOwner = "鈴木";

const keep = primaryOwner;
primaryOwner = backupOwner;
backupOwner = keep;

```

### question

このコードを実行すると何が出力されますか。そうなる理由も説明してください。

### 出力（実行確認）

```

```

### 設計メモ

- **ステージ1（代入で値が変わる）の一段上。** 同じ「代入」を主題にしたまま、
  一時変数を挟むぶんだけ手数が増える。**新しい言語機能を1つも足していないので、前提の借金が無い**
- **コメントは実装と一致している。** 旧2問目（`var` のズレ型）が食い違いを主題にしていたのに対し、
  ここは「コメントの通りに動く」ことを確かめる問題。チュートリアルの2問目で
  「コメントは疑うもの」と教えたくない

  メールアドレス形式にすると PII 検出で採点が拒否される（旧5問目の事故）ので、名前だけを置いている
- `core_reject` は「田中 が出力される」（付け替え前の値）と
  「両方とも 鈴木 になる」（`keep` の役目を読み落とし＝一時変数を使わずに2行書いたときに起きること）

## ステージ 3 ─ レスポンスに無い項目を読む

| 項目 | 値 |
|---|---|
| order | 3 |
| language | js |
| difficulty | **2** |
| reading_type | トレース |
| 収束性 | 記述 |

### code

```js
// GET /api/profile の応答をそのまま受け取ったもの
const profile = {
  id: 1024,
  name: "佐藤",
  age: null,
};

console.log(profile.age);
console.log(profile.company);
```

### question

2つ目の `console.log` は何を出力しますか。1つ目の出力との違いも説明してください。

### 出力（実行確認）

```
null
undefined
```

### 設計メモ

- 主題は旧3問目と同じ「`null` と `undefined` の違い」で、**章に必要な内容なので残した。**
  変えたのは次の3点
  1. **`typeof` を全部外した。** 旧版は `typeof profile.age` が `"object"` になる仕様上の不具合を含んでいて、
     3問目で踏ませる罰としては重い（旧版の設計メモ自身が「そのまま離脱要因になる」と書いている）
  2. **出力を7行から2行に減らした。** 列挙型の設問は矛盾 veto と捏造検出の両方を誤爆させうる
  3. **設問を「2つ目は何が出るか」に絞った。** 旧版は `core` に載る形を探して2度書き直されている
- `core_reject` の1件目は反転（`undefined` ↔ `null`）、2件目は「存在しないプロパティはエラー」の誤解。
  **旧版が明示的に禁じていた `typeof null` 系は `core_reject` に入れていない**（あれは `depth` の材料）
- **キーの不在（`company`）はコード上で「書かれていない」ことが見えるだけ**なので、
  前提知識には `obj.名前` の読み方だけを置いた。`プロパティ` / `undefined` は
  コードに出てこない採点キーワードなので前提知識に書けない（I-817）
