## 何をするか

**最初の5問を「アプリの使い方に慣れるためのチュートリアル」として作り直す。**

いまの並びは実力を測る作りになっていて、**始めたばかりの人が最初につまずく形**になっている。

### 実測した問題（2026-08-26）

**① 難度が階段になっていない**

```
[1] 難度1 ■      const と let
[2] 難度3 ■■■    var が混ざった      ← 2問目で最難関クラス
[3] 難度2 ■■     null と undefined
[4] 難度2 ■■     参照とコピー
[5] 難度3 ■■■    参照が共有される関数
```

**② 最初の5問のうち3問が「うまくいかない話」**

| | 答えの性質 |
|---|---|
| [1] | **エラーで止まる。出力されない** |
| [2] | コメントと実装が食い違っている |
| [5] | 意図と実装が食い違っている |

さらに [6] は `"500"` が文字列で `5002400` になる引っかけ、[7] は `==` のワナ。

**③ 引っかけ型は矛盾検出に当たりやすい**

動作確認用の問題（`id=5`・同じ「const と let」）の実績は
**10件中クリア3件・矛盾検出5件。** 半数が「結論が逆」と判定されている。
矛盾を検出すると0点になるので、**1問目で0点という体験になりやすい。**

---

## なぜ必要か

**最初の数問の仕事は、実力を測ることではなく「やり方に慣れてもらうこと」。**

Ferret は「コードを読んで日本語で説明する」という形式そのものが初めての人が多い。
最初に覚えてもらうのは**答えの出し方ではなく、答え方**。

いまの1問目は「答えは『何も出力されない』」なので、
**「Ferret は引っかけを探すゲームだ」と最初に学習させてしまう。**
これは以降の全問題に効いてくる。

**クリアできないことは離脱の直接の原因**でもある。

### 経験者向けでも最初は簡単にする

**オーナーの方針（2026-08-26）:** ある程度経験がある人向けでも、最初は簡単な問題にする。
**アプリのチュートリアルと同じ位置づけ。**

## 作る問題の条件（ここが本題）

**「難しくない」ではなく「素直」であること。** 難度2でも、読んで追えば答えが出るなら問題ない。

### 満たすこと

| | 条件 |
|---|---|
| **出力がある** | 「何も出力されない」「エラーで止まる」を答えにしない |
| **読めば追える** | 暗黙の型変換・食い違い・ワナを出さない |
| **読解型** | **トレース中心。** ズレ型（食い違いを見つける）は使わない |
| **難度** | 1〜2。**1問目は必ず難度1** |
| **答えが一意** | 「〜が出力される」と言い切れる形。解釈が割れない |

### 避けること

- `==` の暗黙変換、`"500"` のような文字列と数値の混在
- `const` への再代入、例外で止まる系
- コメントと実装の食い違い
- 複数の値を順に列挙させる設問（**箇条書きを誘発し、捏造検出を誤爆させうる** ──
  `ideas/採点システム_残課題.md` §12）

### 難しい点: `core_reject` を2件以上書く必要がある

DB の制約で「言いがちだが違う読み方」を**2件以上**登録しなければならない。
素直な問題ほどここが書きにくい。

**書き方の例:** 出力の順番を取り違える / 変数の値を1つ前の状態で答える。
**引っかけを足して `core_reject` を作らないこと。** 本末転倒になる。

## 手順

1. 上の3点を決める
2. 問題を作る（`ideas/問題作成ガイド.md` に従う）
   - `problems/stage-tutorial.md` と `.sql` のように分けて置く
3. **`order` を決める**
   - 案Aなら、既存の1〜100 を +5 ずらしてから 1〜5 に新しいものを入れる
   - **`id` は書かないこと**（自動採番。書くと `428C9` エラー）
   - `"order"` は予約語なので引用符が要る
4. **`lib/stages/chapters.ts` の章の範囲を直す**
   - 章は `from` / `to` に **order の数字が直書き**されている
   - 案Aで +5 ずらすなら、**全章の数字を +5 する**
5. **`ideas/問題構成案.md` を更新する**（100問の並びが変わるため）
6. `npm run test:db` を通す
   - `I-807`（order の重複）と `I-811`（章の範囲）が効く
7. **ブラウザで1問目から順に解いて確認する**
   - **素直に読んだ答えでクリアできること**
   - **矛盾検出が発動しないこと**（ここが一番大事）
8. `npm test` と `npm run build`

## 注意

- **簡単にしすぎないこと。** ターゲットは新人〜3年目で、完全初心者ではない。
  **「難度を下げる」のではなく「引っかけを外す」**のが軸
