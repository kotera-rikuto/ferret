## 何をするか

2つある。どちらも小さく、まとめてやるのが効率的。

### ① 「よくある勘違い」のどれに当たったかを記録する

問題ごとに「**言いがちだけれど違う読み方**」を登録してある。
例: 「900 が出力されると読んでいる」

AIには渡していて、判定にも使っている。**でも、どれに当たったかを受け取っていない。**
受け取って保存するようにする。

### ② 「どこを見ればいいか」を案内に必ず書かせる

いま読み違いを指摘するとき、
「もう一度上から追ってみてください」のような**場所を示さない案内**が出ることがある。
これでは何をすればいいか分からない。**行や式を必ず示させる。**

---

## なぜ必要か

**①は、問題の改善に使える唯一のデータになる。**

「この問題は、答えた人の3割が同じ勘違いをしている」と分かれば、
問題文が紛らわしいのか、そもそもよくある誤解なのかを判断できる。
いまはその材料が一切ない。

**②は体験の問題。** 間違いを指摘されたうえに、どこを見ればいいか分からないのは、
学習アプリとして最も避けたい状態にあたる。

---

## 手順

### ① 誤読の記録

1. AIの回答の形（`lib/ai/schema.ts`）に項目を1つ足す
   - `matched_reject`。値は「該当なし」か番号（`none` / `1` / `2` / `3`）
   - **必須項目として登録すること。** この仕組みは全項目が必須という決まりになっている
   - 型と検証（`parseDeepScore`）にも同じ項目を足す
2. AIへの指示（`lib/ai/prompt.ts`）に、番号で答えるよう追記する
3. 保存する（`app/api/score/route.ts`）
   - **データベースの変更は不要。** `axes` という欄が自由な形を入れられるので、そこに足す

### ② 案内の具体化

4. `lib/ai/prompt.ts` の指示文（`STATIC_PROMPT`）の feedback の節に追記
   ```
   読み違いを見つけた場合は、それに気づける具体的な箇所（行や式）を必ず示します。
   「もう一度追ってみてください」のような、場所を特定しない案内は書きません。
   ```

### 共通

5. `npm test` を通す
   - **指示文には内容を固定する検査がある**（`tests/unit/__snapshots__/prompt.test.ts.snap`）。
     意図した変更なので、確認したうえで更新する
6. ブラウザで実際に採点し、案内に場所が入っていることを確認する

### 決めたことと、その理由

**1. `matched_reject` は `ComposedScore` ではなく `ScoringResult` に置いた。**
`compose.ts` は「点がどう決まるか」だけのファイルにしてある（依存ゼロで画面からも読める）。
記録用の値を混ぜると、後から読む人が採点要素だと誤解する。型（`DeepScoreOutput`）だけは
AI の出力の形なので compose.ts に置いた。

**2. 検証で既定値（"none"）を埋めない。**
埋めると「モデルが返していない」と「該当なしと判定した」が同じ値になり、
集計したときに “誰も誤読していない問題” と区別がつかなくなる。
モジュール全体の「既定値で埋めない」方針とも揃う。

**3. 番号は 1〜3 まで。** 残課題 §3 の提案どおり。
投入済み6問の `core_reject` は最大3件で、ちょうど収まっている（DB制約は「2件以上」なので上限は無い）。
**4件以上の問題を作るときは `compose.ts` / `schema.ts` / `prompt.ts` の3か所を同時に広げること。**
広げ忘れると4件目以降に当たった回答が黙って `"none"` として記録される。
コメントに明記し、プロンプトの案内範囲とスキーマの enum が揃っていることをテスト（U-160b）で固定した。

**4. `PROMPT_VERSION` を p3 に上げた。** 配点は変えていないが、
同じ "p2" の記録に別々の指示文で採点した行が混ざると、
B1（ゴールデンセット）で前後を比べたときに差の出所が分からなくなる。
副作用として、p2 で採点済みの回答を再送すると再採点になる（1件 約¥0.04）。

**5. 手順④の追記は、既にあった文と重ねない形にした。**
`STATIC_PROMPT` には既に
「行番号・変数名・式など一意に分かるように書く」「“もう一度追ってみてください”のような
場所を特定しない案内は書きません」が入っていた（praise / next_focus を2分割したときに入ったもの）。
指示文を長くすると他の点数帯の文章が悪くなる関係があるため、同じ内容を重ねず、
**「contradiction を true にした、または matched_reject に番号を入れた場合は、
その読み方が成り立たなくなる箇所を必ず入れる」** という条件付きの1文だけを足した。
