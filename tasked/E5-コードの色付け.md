## 何をするか

問題画面のコードに**色を付ける。**

いまは色の無い文字がそのまま並んでいる。
エディタで見るときのように、キーワードや文字列に色が付くだけで読みやすさが大きく変わる。

**Ferret はコードを読ませるアプリなので、ここは体験の中心に近い。**

---

## なぜ必要か

色分けが無いと、`const` なのか変数名なのか文字列なのかを目で拾う必要があり、
**読み取り自体とは関係ないところで疲れる。**

---

## 手順

1. `npm install shiki`
2. 問題画面（`app/problems/[id]/page.tsx`）でコードに色を付ける
   - **この画面はサーバー側で作られているので、色付けもサーバー側でできる。**
     ブラウザに余計な処理を持ち込まずに済む
3. 配色を用意する
   - `design/` のモックで使っている色（`--color-code-` で始まるもの）に合わせる
   - 既存の暗い背景のパネルに載せる前提
4. 言語を出し分ける
   - `problems.language` に `js` か `ts` が入っている
5. `npm run build` を通し、画面で確認する

---

## ⚠️ オーナーに確認すること

**基本的に判断は不要。** ただし1点だけ、作業中に確認すること。

> コードの配色ですが、既存のデザインに合わせた色を自分で作る方法と、
> Shiki に最初から入っている配色をそのまま使う方法があります。
>
> - **自作:** モックの見た目とぴったり合う。手間は少し増える
> - **既製:** すぐ終わる。ただし**画面全体の色合いから浮く可能性**がある
>
> Ferret は暖色系の落ち着いた配色で統一しているので、
> **自作を勧めます**が、まず既製で入れて見比べてから決めることもできます。

### オーナー判断

> **「Shiki 標準の配色を使う」**（自作しない）

既製テーマは40種あるので、**どれを使うかは実装側で選んだ。**
選び方は目分量ではなく、モックが手で塗っていた6色（`design/problem-samples-desktop-light.html` の
`--code-key` / `--code-fn` / `--code-num` / `--code-str` / コメント / 背景）と、
各テーマが同じコードに実際に付ける色を**人の目の感じ方に近い尺度（Lab 色差）で突き合わせた。**

| 順位 | テーマ | トークンの色差 | 背景の色差 |
|---|---|---|---|
| **1** | **gruvbox-dark-hard** | **26.7** | 8.7 |
| 2 | material-theme-darker | 37.9 | 7.6 |
| 3 | tokyo-night | 40.4 | 14.8 |

2位以下は紫のキーワード（VS Code 系）で、Ferret の暖色から離れる。
**1位と2位の差は目で見て分かる程度に開いている**ので、迷う余地は無かった。

### 背景色を差し替えた（判断）

`app/globals.css` の `--color-code-bg` を `#211b12` → `#1d2021`、
`--color-code-ink` を `#ece2cd` → `#ebdbb2`（どちらもテーマの値）に変えた。

**色付きの `<pre>` は自分の背景色を持って出てくる**ので、パネル側の色を変えないと
見出しの帯（JS / 読んでみよう）と本文で背景が食い違い、段差に見える。
どちらも暗色なので**画面上は「そういうデザイン」に見えてしまい、目視では気づけない。**
写し忘れを検知する単体テスト（**U-604**）を置いてある。

`--color-code-edge`（下端の縁）と `--color-code-muted`（見出しの文字）は
パネルの装飾側なので**モックの暖色のまま**にした。

### 詰まった点・気づいたこと

**1. E-455（キーボードだけで回答を送信できる）が落ちている。E5 の変更とは無関係。**
入力欄の次に Tab で当たるのが送信ボタンではなく、注意書きの **「くわしく」リンク**になっている。
このリンクは **C2（法務文書・`a575ea9`）で `ProblemForm.tsx` に足されたもの**で、
コードパネルより後ろにあるため、こちらの変更では動かせない。
**担当外なので直していない**（`tasks/README.md` の「ついでに直さない」）。
送信ボタンへ先に届かせるか、テストの期待値を変えるかの判断が要る。**C3 か、独立した票で拾うのが妥当。**

**2. JS と TS で出力は変わらない。** Shiki の `javascript` 文法は TypeScript 文法の系統なので、
`js` を指定しても型注釈は色分けされる。**「TS のときだけ型が色付く」という検証はできない。**
U-601 は差分ではなく「TS の構文（`interface` / 型注釈）が正しく色付くこと」を見る形にした。
実運用上の影響は無い（どちらの言語でも正しく色が付く）。

**3. Shiki の `<pre>` は自前の背景色と `tabindex="0"` を持って出てくる。**
入れ物が要るので `display:contents` の div で包んでいる（レイアウトには影響しない）。
その結果、**E-451 が見ていた「`<pre>` の親要素の背景色」が入れ物の div になり、
透明でも合格してしまう状態になった。** パネルの枠に `data-code-panel` を付けて、
そちらを直接掴むよう直した。**テストが素通りになる方向の変化なので、放置すると気づけない。**

**4. gruvbox は `return` などの制御キーワードが赤（`#fb4934`）。**
`const` / `function` / `let` はオレンジで、赤はそこだけに出る。
Ferret の他の画面で赤は使っていないが、**コードパネルの中だけの色で、
エラー表示と混同する位置には出ない**ので、そのままにした。
気になる場合は `lib/code/highlight.ts` の import 3行を別のテーマ名に差し替えるだけで変わる。

**5. 対応しているのは `js` と `ts` だけ。** `problems.language` に `ruby` / `python` が入ったら
**色は付かないが画面は普通に出る**（`null` を返して素のテキストに落ちる）。
落ちるより読めるほうがましなので、例外にはしていない（U-602）。
増やすときは `lib/code/highlight.ts` の `LANGS` と import に1行ずつ足す。

### E9（ダークテーマ）への申し送り

**コードパネルの色はもう「モックの暖色」ではなく「Shiki テーマの色」になっている。**
`globals.css` の `--color-code-*` を触るときは、`lib/code/highlight.ts` のテーマと
揃っていること（U-604）を壊さないこと。コードは明色・暗色のどちらでも常にダークなので、
**E9 では `--color-code-*` を切り替えの対象に入れない**のが素直。
