# C5. 本番に公開する（Vercel）

**種別:** 設定作業 + 確認
**規模:** 中
**前提として終わっていること:** **C1・C2・C3・C4 のすべて**

> ### ⚠️ 同時進行の注意
> **他のタスクが動いていないときにやること。** 公開は「いまの `main` をそのまま外に出す」作業なので、
> 途中の変更が混ざると、何を公開したのかが分からなくなる。
> `supabase/config.toml` は C1・C3・C4 も触る。

**先に読むもの**
- `ideas/セキュリティ_残課題.md` の §1-3・§2（**必読**）

---

## 何をするか

**いままでローカル（自分のパソコン）でしか動いていない。** インターネット上に公開する。

---

## ⚠️ 着手前にオーナーに確認すること

> 公開にあたって決めることがいくつかあります。
>
> **① ドメイン（サイトの住所）は決まっていますか**
> 例: `ferret.io`。まだなら、Vercel が自動でくれる住所（`〜.vercel.app`）でも公開できます。
> ただし**後からドメインを変えると、確認メールのリンクなど数か所を直す必要**があります。
> 決まっているなら最初から設定するほうが手戻りがありません。
>
> **② いつ公開しますか**
> - **限定公開**（URLを知っている人だけ）から始めることもできます
> - 検索に出したくない段階なら、検索避けの設定を入れておけます
>
> **③ 費用について**
> Vercel と Supabase はどちらも無料枠から始められます。
> ただし**無料枠の Supabase は1週間使わないと自動で停止**します（過去に一度停止しています）。
> 実際に人に使ってもらう段階になったら有料（月$25程度）への切り替えを検討してください。

---

## 手順

### 1. 公開前の後片付け（先にやる）

1. **開発用アカウントのパスワードを変える**
   - ⚠️ `TASKS.md` と `tasks/README.md` にパスワードが**平文で書かれていて、
     リポジトリは誰でも見られる状態**になっていた（2026-08-22 に削除済み）
   - 公開すると「パスワードが世界に公開されたアカウント」が本番に存在することになる
   - **パスワードを変え、記載のある2か所（`TASKS.md` と `tasks/README.md`）の両方から消すこと**
2. 動作確認用の問題（`order` が 999）を残すか決める
   - **残すことを推奨**（採点が壊れたときの基準になる）。ただし一覧の最後に出る点は確認する
3. `.env.local.example` に必要な項目がすべて載っているか確認

### 2. Vercel の設定

4. リポジトリを Vercel に接続する（`main` に push すると自動で公開される設定）
5. 環境変数を入れる

| 変数 | どこに入れるか |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | すべての環境 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | すべての環境 |
| `SUPABASE_SERVICE_ROLE_KEY` | すべての環境 |
| `OPENAI_API_KEY` | すべての環境 |
| `RESEND_API_KEY` | すべての環境 |
| **`NEXT_PUBLIC_APP_URL`** | **本番だけ。プレビュー環境には入れない** |

> ⚠️ **`NEXT_PUBLIC_APP_URL` をプレビュー環境に入れないこと。**
> 入れると、お試し用の環境からログインした人が**本番へ飛ばされてしまう。**
> 未設定ならアクセス元に合わせて動くので、プレビューは今までどおり使える。

### 3. Supabase 側を本番URLに合わせる

6. 管理画面の Authentication → URL Configuration
   - Site URL を本番のURLにする
   - Redirect URLs に本番のURLと、必要ならプレビュー用のURLを追加
7. `supabase/config.toml` の `site_url` と `additional_redirect_urls` も本番URLに直す
   - **ここまでやって初めて `supabase config push` が安全に使えるようになる**（それまでは禁止）

### 4. 公開後の確認

8. 本番のURLで以下を通す
   - [ ] 新規登録 → **確認メールが届く** → ログイン
   - [ ] ステージ選択 → 問題 → 採点 → リザルト
   - [ ] ログアウト
9. セキュリティの確認（`ideas/セキュリティ_残課題.md` §0 のコマンド）
   - [ ] ブラウザ用の鍵で問題データを直接取ろうとしても**何も取れない**
   - [ ] 特権キーがブラウザ向けのファイルに**含まれていない**
   - [ ] セキュリティ関連の応答ヘッダが付いている

- **`SUPABASE_SERVICE_ROLE_KEY` と `OPENAI_API_KEY` は絶対に `NEXT_PUBLIC_` を付けないこと。**
  付けるとブラウザに配られ、取り返しがつかない（履歴やキャッシュに残る）

## 作業記録

### 2026-08-22 — 公開した

**本番URL: https://ferretcode.com**（暫定の別名 `https://ferret-tau-eight.vercel.app` も生きている）
Vercel プロジェクト `ferret`（`rikuto042700s-projects`）。**GitHub 連携済みで `main` への push で自動公開。**

#### 着手前の3つの確認 → オーナー判断

| | 決定 |
|---|---|
| ドメイン | `ferretcode.com`（C6 で取得済み）を最初から接続 |
| 公開範囲 | **検索避け（noindex）は入れない。** 検索に出したい |
| 公開ゲート1（法務） | **オーナーが法学部なので自分で確認する。** 外部の専門家には出さない |

**検索避けを見送った判断の中身。** 当初は noindex を推したが、**前提が違っていた** ──
`proxy.ts` の matcher が `/stages` `/problems` `/result` `/review` `/settings` を守っているので、
**問題100問はクローラーから見えない。** 外に出るのは `/` `/login` `/register` `/terms` `/privacy` の5枚だけで、
**noindex を入れても出る情報の量は変わらない**（SEO の得も損もほぼ無い）。
本当の論点は **D-1（プラン別の採点上限）が未実装で、登録すれば無制限に採点を回せる**ことだが、
**noindex はその蛇口を締めない**（URL を知っていれば登録できる）。
実効的な守りは **OpenAI 側の使用量上限**のほうで、そちらは未設定のまま残っている（下の「残っていること」）。

#### 手順1（後片付け）で分かったこと ── ⚠️ 平文パスワードは1件ではなく4件だった

本ファイルは `dev@ferret.test` だけを挙げていたが、**テストコードの中に3件あり、
しかも環境変数が未設定だったので既定値が実際に使われていた。**

| アカウント | 平文があった場所 | 対処 |
|---|---|---|
| `dev@ferret.test` | `TASKS.md` / `tasks/README.md` / `tasked/A1` | 乱数。`.env.local` の `DEV_USER_PASSWORD` |
| `e2e@ferret.test` | `tests/e2e/support/fixtures.ts` の既定値 | **特権キーから導出**（保存しない） |
| `db-test-a@ferret.test` | `tests/integration/database.test.ts` | 同上 |
| `db-test-b@ferret.test` | 同上 | 同上 |

**テスト用の3件は保存する代わりに導出する**（`tests/support/password.ts`）。
`sha256(特権キー + ラベル)` なので、リポジトリにも `.env.local` にも残らず、**ズレようがない。**
特権キーを持つ人は元から何でもできるので、ここから新しく漏れるものは無い。
`ensureUser` が**既存アカウントのパスワードを毎回入れ替える**ので、導出式を変えても次の実行で自己修復する。

- **乱数にしなかった理由:** プロセスが分かれると値が変わり、`ensureUser` を通らない spec が
  ログインできなくなる（Playwright は chromium / mobile でプロセスが分かれうる）
- **getter にした理由:** `database.test.ts` は `RUN_DB_TESTS=1` のときだけ `.env.local` を読むので、
  読み込み時に評価すると通常の `npm test` が特権キー無しで落ちる
- ⚠️ **記載を消しても git の履歴には残る。** 実質的な対処はパスワードの変更のほうで、削除は付随

#### Vercel ── タスク文書と2点だけ変えた

| | 判断 |
|---|---|
| `RESEND_API_KEY` を**入れていない** | **アプリのコードが読まない**（送信するのは Supabase）。読まれない鍵を本番に置くと漏れる面が増えるだけ |
| 特権キーと OpenAI キーを **Development に入れていない** | ローカルは `.env.local` を使うので不要。しかも **Development だけ Vercel が Secret にできず Config（読み出せる形）で保存する** |

`NEXT_PUBLIC_APP_URL` は指示どおり **Production だけ**（`https://ferretcode.com`）。

⚠️ **`NEXT_PUBLIC_` 付きの変数は Vercel が secret 扱いを拒否する。**
`--visibility config --no-sensitive` を付けないと `invalid_visibility` で失敗する
（クライアントバンドルに焼き込まれる値なので当然の挙動）。

#### 詰まった点

1. **`vercel git connect` がワークツリーで動かない。** ワークツリーの `.git` はディレクトリではなくファイルなので
   「No local Git repository found」になる。**リポジトリURLを明示すれば通る**
   （`npx vercel git connect https://github.com/kotera-rikuto/ferret.git --yes`）
2. **`vercel link` が `.env.local` に `VERCEL_OIDC_TOKEN` を書き足す。**
   短命トークンで CLI が自動更新するので害はないが、**共有ツリーの `.env.local` が書き換わる**ことは知っておく
3. **Turbopack が「プロジェクト外を指すシンボリックリンク」を拒否する。**
   ワークツリーで `node_modules` を共有ツリーへリンクすると `npm test` は通るが
   `npm run build` が `Symlink [project]/node_modules is invalid` で落ちる。**ワークツリーでは `npm ci` を実行すること**

#### ドメイン ── ネームサーバーは変更しない

Vercel は「A レコードを足す」か「ネームサーバーを `ns*.vercel-dns.com` に変える」の2択を案内してくるが、
**後者を選ぶとメールが止まる。** C6 で入れた Resend の4行はすべてムームーDNS に載っているので、
権威を Vercel に移すと消える。**しかも送信が止まったことに気づけない。**

**A レコード方式を選び、apex に `A 76.76.21.21` を1行足した**（ムームーDNS のカスタム設定）。
足す前に **dig で「Resend の4行が apex に無い」ことを確認済み** ── 実体は
`send.ferretcode.com`（MX・SPF）/ `resend._domainkey`（DKIM）/ `_dmarc`（DMARC）にあり、
**apex は空だったので追加は純粋な足し算だった。** 反映後も4行が無事なことを再確認した。

#### セキュリティの確認（3項目すべて通過）

- **応答ヘッダ:** CSP・`x-frame-options: DENY`・HSTS・`referrer-policy`・`x-content-type-options`・
  `permissions-policy` が本番で付いている。`connect-src` が Supabase の実ホストに解決されており
  **環境変数がビルド時に届いている証拠**にもなる。`unsafe-eval` は無い（本番ビルド）
- **anon キー:** `problems?select=model_answer` と `users?select=*` がどちらも `[]`
- **クライアントバンドル:** `.next/static` の412ファイルを照合し、特権キー・OpenAI キー・
  Resend キー・開発用パスワードのいずれも**含まれていない**（**末尾40文字で照合**。
  JWT の先頭は anon キーと共通なので先頭で見ると誤検知する）
