**種別:** 実装 + 判断
**規模:** 大
**前提として終わっていること:** なし（ただし **C5 公開後**に効く）
**関連:** **M1（集客）とセット。** 記事から来た人の着地点になる

**先に読むもの**
- `ideas/仕様書.md` の「コアコピー」「ターゲット」「マネタイズ」（**言うことは決まっている**）
- `ideas/プレゼン資料.md`（外部向けの言い方が20枚ぶん整理されている。**素材はここにある**）

## 何をするか

**Ferret が何なのかを説明して、登録に繋げるページを作る。**

いまのタイトル画面は**ロゴとボタン2つだけ**で、何のサービスか一切書いていません。
**すでに知っている人しか登録できない状態です。**

広告や記事から来た人が「これは自分に必要か」を判断できるページを用意する。

---

## なぜ必要か

**M1（記事からの集客）の効果が、ここで決まります。**

記事を読んで興味を持った人が最初に見るのがこのページです。
いまの状態だと「ログイン」「新規登録」しか無いので、**大半がそのまま離脱します。**

もう1つ、**広告を作りやすくするため**という目的があります。
広告は「クリックした先で何が言われているか」と揃っていないと成果になりません。
LP があると、広告の文言をそこから取れます。

## 手順

1. 上の6点を決める
2. **`ideas/プレゼン資料.md` から使える文言を抜き出す。** ゼロから考えないこと（20枚ぶんの素材がある）
3. ページを作る
   - ログイン不要で見られること（**`proxy.ts` の `matcher` に足さない**）
   - **既存のデザイントークンを使う**（`app/globals.css`。色を新しく作らない）
   - **ダークテーマでも読めること**（E9 で切り替えが入っている）
   - **スマホで崩れないこと**（記事から来る人はスマホが多い）
4. ログイン済みの人の扱いを決めたとおりに実装（案Aならステージ画面へ送る）
5. 法務文書（利用規約・プライバシーポリシー）への導線をフッターに置く
   - **すでに C2 で作ってある**ので、リンクするだけ
6. 幅375px とパソコン幅の両方で確認
7. `npm test` `npm run build`

- **まだ売っていないものの値段を書かないこと。** 課金は D1・D2 が終わってから

### 決めたことと、その理由

- **ログイン済みの判定は「Cookie が無ければ Supabase に問い合わせない」。**
  LP はいちばん来訪の多いページで、その大半は未ログイン。全員に `getUser()` の往復を待たせると
  表示がまるごとそのぶん遅れる。Cookie がある場合は**中身を信じず `getUser()` で確かめる**
  （`getSession()` は期限切れも偽造も見抜けない）。壊れた Cookie を持たせた実測でも 200 で LP が出る
- **`/` は動的レンダリングになった**（`ƒ` 表示）。Cookie を読むため。データ取得は無いので描画そのものは軽い
- **クリア判定は `lib/ai/compose.ts` の `CLEAR_THRESHOLD` から出す。** デモの点数（86点）に
  「クリア」の札を出すかを定数で決めているので、閾値を変えたときに LP だけ古い判定を出し続けない
- **回答例の文字数（`85 / 600`）も導出。** 上限は `ANSWER_MAX_CHARS`、左は文字列の実長
- **ステージ数・章・問数はすべて `CHAPTERS` から数えている。** 章を増減させても LP は追随する
- **デモの1問は100問のどれでもない、LP のために書いた1問。** 実際の問題を載せると、
  そのステージを解く前に答えが分かってしまう
- **コードは1行30字までに収めた。** `reduce` の1行版（50字）は **1024px 前後のノートパソコンで
  右端が切れた**。横スクロールできる作りなので壊れはしないが、切れた状態が最初に見えると
  「表示が崩れている」と受け取られる。30字なら**幅375pxでも全部見える**
- **主役の惹句は節ごとに `inline-block` で包んだ。** 日本語はどこでも改行できるので、
  素のままだと「読め / る、」のように語の途中で折れる（実測）。大きさは
  **その幅でいちばん狭くなる列**に合わせて5段（`max-[359px]` / 既定 / `sm` / `md` / `lg` / `xl`）
- **節の見出しには `text-balance` と `word-break: auto-phrase` を当てた。** どちらも
  解釈できないブラウザは無視するだけなので、当てておいて損がない
- **半透明のトークン色（`bg-bg/85`・`text-ink/75`）は使わない。** Tailwind はこれを
  `color-mix()` に変え、控えの値として**明るい配色の色をそのまま焼き込む**（実測 `#fdf8ecd9`）。
  暗い配色で `color-mix()` が効かないブラウザに当たると、上部バーだけクリーム色の帯になる
- **マスコットは `neutral`（`character_nobg.png`）だけ。** `happy` / `thinking` には
  透かしが焼き込まれていて、暗い面やアンバーの面に載せると出る（`design/README.md`）

#### ⚠️ CSS だけで作ろうとして1度失敗した（記録）

最初は **`animation-timeline: view()`**（CSS だけでスクロール量を進行度にする仕組み）で
実装した。JavaScript を1行も足さずに済むので筋が良いと判断したが、**これは誤りだった。**

- **`animation-timeline` は Chrome 系だけの機能。** Safari と Firefox は宣言ごと無視する
- 無視されると**読み込み時に1回動く扱い**になり、画面外の見出しはスクロールして
  見るころには動き終わっている ── **動きが無いのと同じ**になる
- ⚠️ **Chromium で計測すると「動いている」と出るので、実測しても気づけない。**
  `animation-timeline: view()` / 待機中8件 / スクロールで opacity 0→1 まで全部確認したが、
  それは Chromium の結果でしかなかった。オーナーの環境で「入っていない」と指摘されて判明
- **教訓: ブラウザごとに実装差がある機能を使ったら、Chromium 以外でも実測する。**
  Playwright には `webkit` と `firefox` が入るので、`npx playwright install webkit firefox`
  で3エンジンとも測れる

#### いまの作り（`components/lp/Reveal.tsx`）

- **`IntersectionObserver`。** どのブラウザにもある。**この部品だけがクライアント側で動き、
  LP 本体はサーバー描画のまま**
- **隠す指定はサーバーの HTML に入れない。** `data-reveal`（`opacity: 0`）を付けるのは
  「JavaScript が動いて、これから動かすと決めた要素」だけ。だから
  スクリプトが届かない人・クローラ・「動きを減らす」設定の人には**そのまま見える**
- **すでに見えている位置の要素は何もしない。** 効果が走るのは最初の描画の後なので、
  見えている要素をそこで隠すと「一瞬出てから消えて、また出る」チラつきになる
- **主役は CSS だけ**（`animate-rise` をサーバー側で付ける）。最初から画面に入っているので
  監視が要らず、チラつきの経路も生まれない
- `rootMargin: "0px 0px -18% 0px"` ── 下端に触れた瞬間ではなく画面の内側まで入ってから
  動かす。0 にすると目に入る位置に来たときにはもう静止している
- **state を持たず DOM を直接触っている。** クラスの付け外しだけで React 側に覚える必要が無く、
  効果の中で `setState` すると描画が余分に走る（`react-hooks/set-state-in-effect` が実際に止めた）
- **付ける場所は LP の見出しだけ。** カードや本文には配っていない ──
  動きを増やすほど作り物に見えるため
