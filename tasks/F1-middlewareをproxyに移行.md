# F1. 非推奨の警告を消す（middleware → proxy）

**種別:** 実装（移行作業）
**規模:** 小
**前提として終わっていること:** なし

> ### ⚠️ 同時進行の注意
> **C2・C3・E1 と同時に進めないこと。** この3つは `middleware.ts` に追記する指示になっており、
> このタスクはそのファイルの名前を変える。
> **できるだけ最初に、単独で済ませること。** そうすれば衝突がまとめて消える。

**先に読むもの**
- `node_modules/next/dist/docs/` の該当ドキュメント（**必読**。バージョン固有の作法があるため）
- `ideas/セキュリティ_残課題.md` の §0（このファイルが何を守っているか）

---

## 何をするか

ビルドのたびに出ている警告を消す。

```
⚠ The "middleware" file convention is deprecated. Please use "proxy" instead.
```

`middleware.ts` という名前のファイルが**古い書き方**になった。
`proxy.ts` に移行する。

---

## なぜ必要か

**いますぐ壊れるわけではない。** ただし2つ理由がある。

1. 古い書き方はいずれ動かなくなる。**動かなくなったときに慌てて直す**より、
   落ち着いているうちに移すほうが安全
2. **このファイルは認証を守っている。** 動かなくなると
   「ログインしていない人が画面を開けてしまう」という形で壊れる。
   後回しにするほど危ない種類のファイル

---

## このファイルが守っているもの（触る前に把握すること）

`middleware.ts` は見た目より重要な仕事をしている。

| 仕事 | 壊れると何が起きるか |
|---|---|
| ログインしていない人を弾く | **誰でも問題や採点結果を見られる** |
| ログイン状態の維持 | ログインしてもすぐ切れる |
| セッションの受け渡し設定 | **セッションが他人に配られる可能性がある** |

**特に3つ目は過去に実際に直した箇所。** `ideas/セキュリティ_残課題.md` に経緯がある。
**動きを変えないこと。** これは引っ越しであって、作り直しではない。

---

## 手順

1. **必ず `node_modules/next/dist/docs/` の該当ドキュメントを読むこと。**
   このバージョンの Next.js は一般的な情報と作法が異なる場合がある
2. `middleware.ts` の中身を `proxy.ts` に移す
   - **中身の処理は一切変えない**
   - 保護対象の一覧（`matcher`）も同じにする
3. 古いファイルを削除する
4. **確認する**
   - ログインしていない状態で `/stages` を開くとログイン画面に飛ぶ
   - `/problems/1` `/result/1` `/review/1` も同じ
   - ログイン後、**元のページに戻る**（この動きも維持されているか）
   - ログインした状態で画面を移動しても、ログインが切れない
5. `npm test` と `npm run build`
   - **警告が消えていることを確認**

## 作業記録

**実施: 2026-08-17 / ブランチ: `worktree-f1-middleware-to-proxy`**

### やったこと

`middleware.ts` を `proxy.ts` に改名し、関数名を `middleware` → `proxy` に変えた。
**処理は1行も変えていない。** `git mv` で移したので git 上も類似度98%の rename として記録され、
ファイル内の差分は関数名の1行だけ。

参照していた側も呼び名を揃えた。

| ファイル | 変更 |
|---|---|
| `middleware.ts` → `proxy.ts` | 改名 + 関数名 |
| `tests/integration/auth-routes.test.ts` | import・呼び出し9箇所・コメント |
| `tests/integration/architecture.test.ts` | `@/middleware` → `@/proxy`・コメント |
| `app/auth/callback/route.ts` / `app/login/page.tsx` | コメント内の呼び名 |
| `lib/supabase/cookies.ts` / `lib/supabase/server.ts` | コメント内の呼び名 |
| `ideas/セキュリティ_観点.md` / `tasks/*` / `残タスク.md` / `TASKS.md` | ファイル名の記述 |

### 決めたこと・理由

**公式 codemod（`npx @next/codemod@canary middleware-to-proxy .`）は使わず手で移した。**
やることは「ファイル名」と「関数名」の2つだけで、canary パッケージをネットワークから
落とす必要がない。`git mv` を使えば rename として記録されるので履歴も素直。

**名前付き export（`export async function proxy`）にした。**
ドキュメントは default export も認めているが、`config` を併せて export する既存の形を
保つほうが差分が小さい。

**コメント内の「middleware」も直した。** F1 の指示は「中身の処理をついでに整理しないこと」だが、
これは処理ではなく**改名した対象の呼び名。** 残すと次の人が `middleware` で grep して
何も見つけられなくなる。処理には触っていない。

### 詰まった点（次に同じことをする人へ）

**ワークツリーが `origin/main` から切られ、未 push のコミット14件が入っていなかった。**
その中に `5fb5182 ログイン画面へのリダイレクトにもキャッシュ禁止を載せる` ——
**まさにこのタスクが「壊すな」と警告していたセキュリティ修正** —— が含まれていた。
気づかずに移植すると、修正前の `middleware.ts` を `proxy.ts` として復活させることになっていた。
ローカル `main` に `git reset --hard` して合わせてから作業した。

> **ワークツリーの基点は既定で `origin/<既定ブランチ>`。** ローカル `main` のほうが
> 進んでいることがあるので、切った直後に `git log HEAD..main` で確認すること。

**Next.js は `middleware` と `proxy` の両方があるとビルドを止める**（エラーコード E900）。
片方を消す必要があるので、`git mv`（＝旧ファイルの削除を伴う）が正しいやり方だった。

**`proxy` は `runtime` の指定を受け付けない**（指定すると例外）。元は指定していなかったので影響なし。
Next.js 16 では proxy の既定が Node.js ランタイム。

### 確認したこと

| 項目 | 結果 |
|---|---|
| ビルドの非推奨警告 | **消えた。** ルート表示も `ƒ Proxy (Middleware)` に変化 |
| 開発サーバーの警告 | 出ない（警告は `middleware` ファイル検出時のみ発火することを Next 本体のコードで確認） |
| 未ログインの `/stages` `/problems/1` `/result/1` `/review/1` | 4つとも 307 → `/login?next=…`（実サーバーに curl） |
| 公開画面 `/` `/login` `/register` | 200 のまま（matcher が広がっていない） |
| ログイン後に元の場所へ戻る | `/stages`・`/problems/1` 両方で復帰（ブラウザ実測） |
| ログイン状態の維持 | 再訪してもログイン画面へ飛ばない（ブラウザ実測） |
| `npm test` | 通る（matcher の検査 I-395 を含む） |
| `npm run lint` / `npm run build` | 通る |

ブラウザでの確認時、開発サーバーのログに `GET /stages 200 ... proxy.ts: 217ms` と出ており、
**実際に `proxy.ts` が実行されている**ことも裏取りできている。

### 2. E2E `tests/e2e/auth.spec.ts` が7件落ちている（F1 とは無関係）→ `tasks/F3` として起票済み

**移行前のコードでも同じ落ち方をすることを確認済み**なので、F1 が原因ではない。原因は2つ。

1. **アサーションが古い。** `getByRole("heading", { name: "ログイン" })` を待っているが、
   デザイン移植（`943345a`）でログイン画面の見出しは**「おかえりなさい」**に変わっており、
   「ログイン」は送信ボタンのラベルにしか残っていない
2. **`allowedDevOrigins` が未設定。** E2E の baseURL は `http://127.0.0.1:3100` だが、
   Next.js 16 は `127.0.0.1` からの dev リソース取得を既定で遮断する。JS が読めず
   ハイドレーションが起きないため、フォーム送信そのものが動かない。
   `next.config.ts` に `allowedDevOrigins: ['127.0.0.1']` を足すか baseURL を `localhost` にすれば直る

**リダイレクトのアサーション（`toHaveURL(/login?next=…/)`）は移行後も通っている。**
落ちているのは見出しとハイドレーションの部分だけ。

そのため F1 の確認は `localhost` を使う使い捨てスクリプトで代替した（5/5 通過）。
**E2E の修復は F1 の範囲外なので手を付けていない。別タスクとして起票することを勧める。**
