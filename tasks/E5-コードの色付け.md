# E5. コードを色分けして読みやすくする（Shiki）

**種別:** 実装
**規模:** 中
**前提として終わっていること:** なし

> ### ⚠️ 同時進行の注意
> **同時に進めてはいけない相手は無い。** ただし
> `app/problems/[id]/page.tsx`（E4・E8・G2）／`app/globals.css`（E9）を共有する。
> **着手前に `main` を取り込むこと。**

**先に読むもの**
- `design/移植残タスク.md` の §5
- `design/problem-desktop-light.html`（色の付いた状態のイメージ）

---

## 何をするか

問題画面のコードに**色を付ける。**

いまは色の無い文字がそのまま並んでいる。
エディタで見るときのように、キーワードや文字列に色が付くだけで読みやすさが大きく変わる。

**Ferret はコードを読ませるアプリなので、ここは体験の中心に近い。**

---

## なぜ必要か

色分けが無いと、`const` なのか変数名なのか文字列なのかを目で拾う必要があり、
**読み取り自体とは関係ないところで疲れる。**

---

## 手順

1. `npm install shiki`
2. 問題画面（`app/problems/[id]/page.tsx`）でコードに色を付ける
   - **この画面はサーバー側で作られているので、色付けもサーバー側でできる。**
     ブラウザに余計な処理を持ち込まずに済む
3. 配色を用意する
   - `design/` のモックで使っている色（`--color-code-` で始まるもの）に合わせる
   - 既存の暗い背景のパネルに載せる前提
4. 言語を出し分ける
   - `problems.language` に `js` か `ts` が入っている
5. `npm run build` を通し、画面で確認する

---

## ⚠️ オーナーに確認すること

**基本的に判断は不要。** ただし1点だけ、作業中に確認すること。

> コードの配色ですが、既存のデザインに合わせた色を自分で作る方法と、
> Shiki に最初から入っている配色をそのまま使う方法があります。
>
> - **自作:** モックの見た目とぴったり合う。手間は少し増える
> - **既製:** すぐ終わる。ただし**画面全体の色合いから浮く可能性**がある
>
> Ferret は暖色系の落ち着いた配色で統一しているので、
> **自作を勧めます**が、まず既製で入れて見比べてから決めることもできます。

## 注意

- **色付けはサーバー側で行うこと。** ブラウザ側でやると、
  読み込むファイルが大きくなり、色が付くまで一瞬遅れる
- コードが長い問題でも表示が崩れないか確認すること
- E4（影響型の2枠表示）を先に済ませている場合、
  **実行結果の枠には色を付けないほうがよい**（エラー文はコードではないため）。
  判断がつかない場合は確認を取ること
