## 何をするか

マスコットの動きを、**いまの簡単な揺れより凝ったもの**（歩く・しっぽを振る・のけぞって喜ぶ など）にする。
その動きを再生するための仕組みが Lottie。

> ### ⚠️ この作業の本体は「絵」であって「プログラム」ではない
> **再生する仕組みを入れるだけなら半日で終わる。**
> 動く絵のデータが無いと、仕組みを入れても**再生するものが何も無い。**
> だから手順1は「素材を用意する」から始まる。

---

## なぜ必要か

- いまの動きは7種類だが、**どれも1枚の絵を揺らしているだけ**
  （ふわふわ浮く / 採点中に鼻を動かす / ぽんと出る / 現在地の光の輪 / 吹き出しの上下 / 点滅 / 紙吹雪）
- 表情の絵は3枚（通常・喜ぶ・考える）あるが、**切り替わるだけで、その間の動きが無い**
- この種のアプリでマスコットが効くのは「こちらの操作に反応が返ってきた」と感じられるとき。
  静止画の差し替えでは、そこまで届かない

## ⚠️ オーナーに確認すること

### ① 動く絵のデータを、誰がどうやって用意しますか

> **これが決まらないと着手できません。** 仕組みだけ入れても、再生するものがありません。
>
> - **案A: まず1つだけ試作する**（おすすめ）
>   1つあれば「思ったとおりに動くか」「重くならないか」を確かめられます。
>   **10個作ってから「重すぎる」と分かるのが最悪の順番**です
> - 案B: 外注する
>   まとまった費用と、キャラの資料を渡すやり取りが要ります
> - 案C: 自分で作る
>   専用のソフト（After Effects など）と描く時間が要ります
>
> **どの案でも、②で「どこを動かすか」を先に決めておくと、作る枚数が決まります。**

### ② どの場面を動かしますか

> マスコットは **9ファイル・12か所**に出ています。大きさは**とても小さいもの（横 26px 相当）から
> タイトル画面の大きなもの（横 280px 相当）まで**幅があります。
>
> - **案A: 大きく出る3か所だけ**（おすすめ）
>   タイトル画面 / 採点を待っている間 / リザルトの登場。**動かす価値があるのはこの3つ**です
> - 案B: 全部
>   サイドバーの隅などにある小さいマスコットは、**動かしても見えません。**
>   その割に読み込むデータだけ増えます
>
> **案Aなら、用意する素材は3つで足ります。**

### ③ タイトル画面を動かす場合、最初の表示をどうしますか

> タイトルは**アプリを開いて最初に目に入る絵**です。いまは画像なので**開いた瞬間に出ます。**
> 動く絵に替えると、**読み込みを待つぶんだけ出るのが遅れます。**
>
> - **案A: まず今の画像を出し、準備ができたら動く絵に差し替える**（おすすめ）
>   表示の速さを落とさずに動きを足せます。作りは少し増えます
> - 案B: タイトルは今の画像のままにして、他の2か所だけ動かす
>   いちばん安全。**最初の表示速度に一切触りません**
> - 案C: 読み込みを待たせる
>   作りはいちばん簡単ですが、**最初の画面が一瞬空白になります**

## 手順

1. **素材を1つ用意する**（②で決めた場面のうち1つ）。ここが済むまで先に進まない
2. ライブラリを入れる（`lottie-react` か `@lottiefiles/dotlottie-react`）。
   **入れる前と後で `npm run build` の出力サイズを控えて、増加量を作業記録に書く**
3. **`components/ui/MascotMotion.tsx` を新規で作る。`Mascot.tsx` は静止画のまま残す**
   - **理由:** `Mascot.tsx` は `app/page.tsx` `app/stages/page.tsx` `app/problems/[id]/page.tsx`
     などサーバーコンポーネントから使われている。Lottie はブラウザ側でしか動かないので `"use client"` が要る。
     1つのファイルにまとめると、**静止画で足りている9か所まで JS を背負うことになる**
   - 静的 import の PNG は `next/image` が寸法を把握している。差し替えるときは
     **同じ表示サイズになるか**を目で確認する（3枚ともキャラの占有率を揃えてある。`Mascot.tsx` のコメント）
4. ②で決めた場面だけ `MascotMotion` に差し替える
5. **`prefers-reduced-motion`（OS の「動きを減らす」設定）に対応する**
   - **現状 `app/globals.css` は未対応で、いまの CSS アニメも止まらない。**
     無限に繰り返す動きが増えるので、ここで一緒に入れる
6. 差し替えた場所の CSS アニメ（`animate-float` `animate-sniff` `animate-pop`）を外す。
   **外し忘れると、Lottie の動きと CSS の揺れが二重にかかる**
7. `npm test` と `npm run build` を通す

## 注意

- **素材の当てが無いうちにライブラリだけ入れないこと。** 使われないコードが残り、
  次に見た人が「何かに使われているはず」と考えて消せなくなる
- **採点待ちの動きは短くする。** 実測の待ち時間は **1.2〜4.3秒**。
  長い動きを作ると、1周する前に画面が切り替わって尻切れになる
- **喜ぶ動きはクリアしたときだけ。** 不合格の画面に出さない（`Mascot.tsx` のコメントと、
  `CLAUDE.md` のネガティブ表現を避ける方針）
- **紙吹雪（`fall`）・現在地の光の輪（`halo`）・点滅（`blink`）はマスコットではない。**
  これらは CSS のままでよく、Lottie にする対象ではない
