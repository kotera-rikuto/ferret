# C3. せってい画面（退会・パスワード変更・メールアドレス変更）

**種別:** 実装
**規模:** 大
**前提として終わっていること:** メールアドレス変更のみ **C1**（メール送信）が先
**関連:** C2（プライバシーポリシー）で「退会時にデータを消すか」を決めておくと手戻りがない

> ### ⚠️ 同時進行の注意
> **F1（`middleware.ts` の移行）と同時に進めないこと。** ファイル名が変わる。
> **F1 が済んでいる場合は、`middleware.ts` ではなく `proxy.ts` を見ること。**
> `app/settings/page.tsx` は D2・E9 も触る。`supabase/config.toml` は C1・C4・C5 も触る。
> 着手前に `main` を取り込むこと。

**先に読むもの**
- `design/定番機能リスト.md` の B
- `ideas/セキュリティ_残課題.md` の §4「画面を追加するとき」（**必読**）
- `app/api/feedback/route.ts`（新しいAPIを作るときの手本）

---

## 何をするか

サイドバーに「せってい」が**準備中として置いてある**。中身を作る。

| 機能 | 必要度 |
|---|---|
| **退会（アカウント削除）** | **公開前に必須** |
| パスワード変更 | あるとよい（実装は軽い） |
| メールアドレス変更 | あるとよい（**C1 が先**） |

---

## なぜ必要か

**個人情報を預かる以上、「やめたい」と言われたときに消せる必要がある。**
退会の手段が無いまま公開するのは避けたい。

パスワード変更とメールアドレス変更は、無くても公開はできるが、
「設定画面を開いたのに何もない」状態は体験として良くないので、まとめて作る。

---

## ⚠️ オーナーに確認すること

**退会したときに何を消すか。これは着手前に必ず決めること。**

> 退会したとき、その人のデータをどう扱いますか。
>
> **案A: 全部消す**
> ログイン情報も、回答の履歴も、異議申し立ての内容も消します。
> - よい点: 「消してほしい」に完全に応えられる。分かりやすい
> - 悪い点: **問題の改善に使っていたデータも消えます。**
>   「この問題は3割が同じ勘違いをする」といった集計から、その人の分が抜けます
>
> **案B: ログイン情報だけ消し、回答は誰のものか分からない形にして残す**
> - よい点: 問題の改善に使えるデータが残る
> - 悪い点: 「残っている」ことを**プライバシーポリシーに明記する必要**があります（C2と関係）。
>   説明の手間が増えます
>
> **決め方の目安:** いま利用者はほぼいないので、**案A（全部消す）で始めるのが安全**です。
> 説明が要らず、後から案Bに変えることもできます（逆は難しい）。
>
> どちらにしますか。

あわせて確認:

> 退会するときの確認方法はどうしますか。
> - **案A: パスワードをもう一度入力させる**（おすすめ）
> - 案B: 「削除」と入力させる
>
> 案Aを勧めるのは、**パソコンを離席したときに他人に消されるのを防げる**ためです。

## 手順

### 1. 画面の枠

1. `app/settings/page.tsx` を作る
2. **`middleware.ts` の保護対象に `/settings` を追加する**（ログインが要る画面のため）
3. サイドバー（`components/layout/AppSidebar.tsx`）の「準備中」を外してリンクにする

### 2. パスワード変更（一番軽い）

4. 画面から `supabase.auth.updateUser({ password })` を呼ぶ
5. **C4 とセットで、古いパスワードの入力を必須にする設定を有効にする**
   （`supabase/config.toml` の `secure_password_change`）

### 3. メールアドレス変更（**C1 の後**）

6. `supabase.auth.updateUser({ email })` を呼ぶ
7. 新しいアドレスに確認メールが届く。**メール送信が動いていないと使えない**

### 4. 退会（一番重い）

8. サーバー側のAPIを作る（例: `app/api/account/delete/route.ts`）
   - **先頭に `isCrossSiteRequest` と `hasJsonContentType` を置く**（共通の決まりごと）
   - ログインしている本人か確認する
   - 上で決めた確認方法（パスワード再入力など）を検証する
   - 特権キー（`lib/supabase/admin.ts`）でアカウントを削除する
   - 案Aなら、関連するデータも消す
9. 削除後はログアウトさせてタイトル画面へ戻す

### 5. 仕上げ

10. `npm test` と `npm run build` を通す
11. **実際に捨てアカウントを作って退会まで通す**

## 終わったと言える条件

- [ ] 退会時のデータの扱いについてオーナーの判断を得ている
- [ ] ログインしていない状態で `/settings` を開くとログイン画面に飛ぶ
- [ ] パスワードを変更でき、変更後の新しいパスワードでログインできる
- [ ] 退会できて、**そのアカウントでログインできなくなる**
- [ ] 退会後にデータが（決めたとおりに）消えている／残っている
- [ ] `npm test` と `npm run build` が通る

---

## 注意

- **退会は取り消せない。** 押し間違いを防ぐ確認を必ず入れること
- **特権キーを使うAPIでは、必ず自分で本人確認をすること。**
  特権キーは「誰が呼んでいるか」を見ないので、確認を忘れると
  **誰でも他人のアカウントを消せるAPI**になる
- **開発用アカウント（`dev@ferret.test`）を消さないこと。** 動作確認で使っている
- 退会の処理を書くときは、`user_attempts` と `problem_feedback` が
  そのユーザーを参照している点に注意（消す順番を誤ると失敗する）
