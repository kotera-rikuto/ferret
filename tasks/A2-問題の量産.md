# A2. 残り94問を作る

**種別:** コンテンツ作成
**規模:** 特大（複数セッションに分ける前提）
**前提として終わっていること:** **A1 必須・B1 必須**
**関連:** E4（前提知識の欄）を入れるなら、**着手前に方針を決めておくこと**

> ### ⚠️ 同時進行の注意
> **A1・B1 と同時に進めないこと。** A1 とは**表示順の番号が重複する**（`npm run test:db` が検出）。
> B1 とは、測っている最中に対象が増えて比較できなくなる。
> **章ごとに分けて複数セッションで進める場合も、同時に走らせないこと。**
> 番号の重複を避けるため、**1章ずつ順番に**行う。
> アプリのコードは触らないので、コードの衝突は起きない。

**先に読むもの**
- `ideas/問題作成ガイド.md`（**必読**）
- `ideas/問題構成案.md`（100問の一覧）
- `problems/stage-001-005.md` と `.sql`（手本）
- A1 の作業記録（読ませ方ごとの注意点）

## 何をするか

100問の構成のうち、**残り94問を作って登録する。**

## なぜ必要か

**これが唯一の停滞要因。** 仕組みは動いているので、あとは中身。

5問では「積み上げて登る」体験にならない。

---

## ⚠️ 着手前に必ず確認すること

### 1. A1 と B1 が終わっているか

**終わっていないなら、このタスクを始めてはいけない。**

採点の物差しが固まる前に量産すると、後で調整が入ったときに
**作った問題の採点基準を全部書き直すことになる。** これが一番高くつく失敗。

### 2. 前提知識を入れるかどうか（E4 で決まっているはず）

> 各問題に「この問題を解くのに必要な予備知識」を付ける構想があります（E4）。
> **これを入れるなら、問題を作り始める前に決めてください。**
>
> - **入れる場合:** 1問あたりの作業が増えます（解説を1本書くぶん）。
>   ただし94問すべてに一度に書くので、後から追加すると**94問を作り直すことになります**
> - **入れない場合:** いまの形式のまま進めます。後から足すなら、
>   そのとき改めて94問ぶんの解説を書くことになります
>
> **いま決めるほうが安いです。**

### 3. 進め方

> 94問をどう進めますか。
>
> - **案A: 章ごとにまとめて作る**（第1章8問 → 第2章8問 …）
>   関連する内容が続くので作りやすい。ただし後半の章の問題が長く未検証のまま
> - **案B: 各章から少しずつ作る**
>   全体の難易度バランスを早く見られる。ただし文脈が飛ぶので作りにくい
>
> **おすすめは案A**です。1章ぶん（8問前後）が1セッションの区切りとして扱いやすく、
> `npm run test:db` の健全性チェックも章単位で回せるためです。

---

## 手順

**1章ぶん（8問前後）を1セッションの単位にする。**

1. `ideas/問題構成案.md` から対象の章を選ぶ
2. 章内の各問題について `ideas/問題作成ガイド.md` に従って作る
3. `problems/stage-XXX-YYY.md` に中身、`.sql` に登録用SQLを書く
   - **`id` は書かない**（自動で振られる。書くとエラー）
   - `"order"` は引用符が必要
4. Supabase の SQL Editor で登録
5. **`npm run test:db` を実行**（健全性チェック。下記参照）
6. 章の中から**2〜3問を抜き取ってブラウザで実際に解く**
   - 全問やる必要はないが、**新しい読ませ方を使った問題は必ず解くこと**
7. `ideas/問題構成案.md` に進捗の印をつける

### `npm run test:db` が見てくれること

自動で以下を確認してくれる。**登録したら必ず流すこと。**

- 模範解答がキーワードで満点を取れるか
- キーワードが設問文に入っていないか（写して点が入るのを防ぐ）
- 採点基準の中核が1つに絞れているか
- 表記のゆれが十分あるか
- 順番の重複・タイトルの重複がないか
- キーワードがちょうど4組あるか
- 章の範囲に収まっているか

## 注意

- **設問文にキーワードを書かない。** 回答者が写すだけで点が入る
- **中核の判定は「結論を1つだけ」書く。** 2つ以上詰めると、正しいが短い回答が落ちる
  （`ideas/問題作成ガイド.md` に実例あり）
- **「よくある勘違い」は2件以上必須。** データベース側で強制されている
- 途中で採点の物差しを変えたくなったら、**そこで量産を止めて B3 に移ること。**
  変えてから残りを作らないと、前半と後半で基準が変わる
- **1問あたりの費用感:** 作った問題の動作確認で数回採点するので、1問あたり数円程度
