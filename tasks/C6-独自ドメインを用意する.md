## 何をするか

**Ferret 専用のドメイン（`〇〇.com` のような住所）を1つ用意して、2か所に登録する。**

1. **Resend**（メール送信）に登録 → 確認メールが**誰のアドレスにも届くようになる**
2. **Vercel**（公開先）に設定 → 本番URLがそのドメインになる

---

## なぜ必要か

**いまの状態では、iCloud を使っている人が登録できない。** 2026-08-17 に実測して分かった。

C1 では、送信元として Resend が用意しているお試し用アドレス（`onboarding@resend.dev`）を使った。
仕組みは全部動いた（送信・日本語の文面・リンクからのログイン）。**ただし実際のアドレス宛に送ったら拒否された。**

```
宛先 rikuto042700@icloud.com  →  Bounced
理由 Blocked due to content: The message was rejected because it contained
     content that the recipient's server doesn't allow.
```

原因は2つあり、**デプロイで消えるのは片方だけ。**

| 原因 | どうなるか |
|---|---|
| リンクが `http://localhost:3000` を指している（暗号化なし・外から到達できない宛先） | **デプロイで解決する見込み。** `https://` の本番URLになれば、この引っかかりは消える |
| 差出人が共用のお試しドメイン | **デプロイでは解決しない。** Resend でのドメイン認証が必要 |

2つ目が残る理由。メールが本物かどうかは**差出人ドメインの持ち主が送信を許可しているかをDNSで照合して**判定される。
`resend.dev` は Resend の共用ドメインで、Ferret として認証されたものではない。
Resend 公式も「送信にはドメインの追加と認証が必要」と明記している。
**今回 iCloud まで到達したのは、宛先が Resend アカウントの持ち主本人だったからで、他人のアドレス宛は Resend 側で止まる可能性が高い**（未検証）。

> **`*.vercel.app` では代用できない。** Resend の認証にはDNSを触る必要があり、`vercel.app` は Vercel のものなので触れない。

## 手順

1. ドメインを取得する（上の確認で決めたもの）
2. **Resend にドメインを登録する**
   - Resend → Domains → Add Domain
   - 表示される3行（DKIM / SPF 相当）をドメインのDNS設定に貼る
   - `Verified` になるまで待つ（数分〜数時間）
3. **Supabase の送信元を変える**
   - Project Settings → Authentication → SMTP Settings
   - Sender email を `noreply@<取得したドメイン>` に変更（Sender name は `Ferret` のまま）
4. **Supabase の URL 設定を本番向けにする**（C5 と重なる部分。順番はどちらでもよい）
   - Authentication → URL Configuration → Site URL を `https://<ドメイン>` に
   - `additional_redirect_urls` に開発用（`http://localhost:3000`）を残す
5. **確認メールの文面を再反映する**
   - `node supabase/templates/apply.mjs`（`supabase/templates/README.md` 参照）
   - **これで C1 で残した件名の日本語化も同時に片付く**（スクリプトに入っている）
   - 実行には Auth の**書き込み権限**を含む Personal Access Token が必要
6. **`supabase/config.toml` の `site_url` / `additional_redirect_urls` を本番URLに直す**
   - ここまでやれば `supabase config push` が安全に使えるようになる（いまは実行禁止）
7. **実配信を確認する**
   - **iCloud のアドレスで登録して届くこと**（今回弾かれた経路。ここが本題）
   - Gmail でも届くこと
   - **迷惑メールフォルダに入らないこと**

## 手順（この順に。上のオリジナルの手順を、決定後の実物に合わせて書き直したもの）

### 1. ドメインを取得する

ムームードメインで `ferretcode.com` を申し込む。**支払いは「銀行振込」。契約年数は複数年でまとめる。**

| 申し込み画面の項目 | 選ぶもの | 理由 |
|---|---|---|
| WHOIS公開情報 | **「弊社の情報を代理公開する」** | 既定のままだと**登録者の氏名・住所・電話番号が誰でも検索できる形で公開される。** リポジトリが Public で、`lib/legal.ts` に住所を載せていない判断（`tasks/C2`）がここで無意味になる |
| ネームサーバ（DNS） | **ムームーDNS** | 手順3で Resend のレコードを足す場所になる |
| ムームーメール等のオプション | **不要** | 差出人は `noreply@` で、受信しない |
| **契約年数** | **複数年（3年を目安）** | 下記。**自動更新が使えないぶんをここで埋める** |
| 支払い方法 | **銀行振込** | 下記 |

> #### ⚠️ このアカウントでは自動更新が使えない。**復活を待つ運用にしないこと**
>
> 自動更新の対象は**クレジットカード決済と「おさいぽ！決済」だけ**（ムームー公式ヘルプ
> 「自動更新の設定・解除について」）。オーナーはカードを持たず、
> **「おさいぽ！」は「現在、メンテナンス中につき、おさいぽ認証をご利用できません」の表示が
> 出たまま選択できない。** 2026-08-18 に実機で確認し、オーナーによれば**4年ほど前から同じ状態。**
> **一時的な障害ではなく実質廃止とみなす。**
>
> ドメイン取得後にあとから自動更新をONにする経路も、結局おさいぽかカードが要るので**塞がっている。**
>
> #### 代わりに複数年でまとめて登録する（これが構造的な対策）
>
> `.com` は **1〜10年**をまとめて登録できる。
> **このプロダクトで更新忘れによる失効が起きると、サイトとメールが同時に止まる** ──
> 確認メールが送れなくなるので、既存ユーザーだけでなく**新規登録の経路ごと死ぬ。**
> 仕組み（自動更新）で防げない以上、**年数を先に買って発生頻度そのものを下げるしかない。**
> **3年を目安**とする（10年は、まだ公開もしていないプロダクトに対して過剰）。
>
> #### 更新のお知らせメールの宛先に注意
>
> ムームーは有効期限の **30日前・15日前・10日前・2日前・1日前・当日**に通知メールを送る。
> **この宛先を `ferretcode.com` のアドレスにしないこと。**
> ドメインが切れればメールも止まるので、**失効を知らせるメールが失効によって届かなくなる。**
> 個人のメール（Gmail 等）にすること。
> 加えて、**取得できたら更新期限をカレンダーにも入れる**（通知メールを見落とす前提で二重にする）。

> #### ⚠️ 振込依頼人名に `MU＊＊＊＊＊` を入れる（忘れると入金が紐づかない）
>
> ムームーの支払い画面に `MU` で始まる英数コードが出る。**振込依頼人名（払込人名義）の欄を、
> 自分の名前ではなくこのコードにして振り込む。** 入れ忘れると、入金があっても注文と結びつかない
> （公式ヘルプに「入金の際に『MU000000XX』を入力し忘れました」という専用記事があるほど頻出）。
> ゆうちょ銀行アプリ・ゆうちょダイレクトのどちらでも、依頼人名は編集できる。
>
> **土日祝は入金確認されない。** 締切日が土日祝にかかる場合は、平日の
> 窓口 13:30 / ATM 14:30 までに済ませること。入金確認まで数日かかることがある。

- **入金の反映を待つ。** 振込は反映が翌営業日になることがある

### 2. Resend にドメインを登録する

Resend → **Domains** → **Add Domain** → `ferretcode.com`

**サブドメイン（`mail.` など）にしないこと。** Resend はサブドメインを推奨しているが、
それだと差出人が `noreply@mail.ferretcode.com` になり、`noreply@ferretcode.com` にする決定と食い違う。
ルートドメインを登録しても、Resend は送信用の値を `send.ferretcode.com` の下に作る。

表示される **MX 1件・TXT 2件**（SPF と DKIM）を控える。

### 3. ムームーDNS にレコードを貼る

コントロールパネル → **ドメイン管理 → ムームーDNS** → 対象ドメインの **「変更」** → **カスタム設定**

設定できるのは A / MX / CNAME / SRV / AAAA / ALIAS / CAA / NS / **TXT**（SPF・DKIM を含む）の9種類。

> #### ⚠️ ここが一番間違えるところ（2つ）
>
> **① サブドメインの欄には、ドメイン部分を除いた部分だけを入れる。**
> Resend が `send.ferretcode.com` と表示していたら、欄に入れるのは **`send`** だけ。
> `send.ferretcode.com` と入れると `send.ferretcode.com.ferretcode.com` になり、**永久に `Verified` にならない。**
> ルートドメイン（`ferretcode.com` そのもの）宛のレコードは**空欄**にする。
>
> **② MXレコードの値は、末尾のドットまで含めて貼る。**
> `feedback-smtp.xxxx.amazonses.com.` の最後の `.` を落とすと、後ろにドメイン名を足されることがある。

- MX の優先度は Resend の表示どおり（通常 `10`）
- **すべて入力し終えてから「セットアップ情報変更」を押す。** 押し忘れると1件も保存されない
- **反映まで1時間程度かかる**（ムームー公式の案内）。手順4の待ち時間はこれを見込むこと

### 4. `Verified` になるまで待つ

数分〜数時間かかる。**`Verified` になる前に送っても改善しない。焦って設定を変え直さないこと。**

### 5. Supabase の送信元を変える

Project Settings → **Authentication → SMTP Settings**

- Sender email: **`noreply@ferretcode.com`**
- Sender name: `Ferret` のまま

### 6. Supabase の URL 設定を本番向けにする

**Authentication → URL Configuration**

- Site URL: **`https://ferretcode.com`**
- Redirect URLs に **`http://localhost:3000` を残す**（消すとローカル開発でログインの戻り先が全部弾かれる）

> #### この手順の副作用（把握しておくこと）
>
> Site URL を本番にすると、**ローカルで新規登録したときの確認リンクも `https://ferretcode.com` を指す。**
> C5（デプロイ）が終わるまで、そのリンクは開けない。
> 開発用アカウント（`dev@ferret.test`）は確認済みなので普段の開発は困らないが、
> **ローカルで登録の通しを試したくなったら Site URL を一時的に戻すこと**（戻したら必ず本番に直す）。
