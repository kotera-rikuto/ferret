## 何をするか

**いまの画面はパソコン向けに作られている。**
横幅が狭い端末では、左のメニューと右側の情報を消して、簡易的な見出しで代用している。

スマホでちゃんと使える形にする。

---

## なぜ必要か

このジャンルのアプリは**移動中や隙間時間に使われることが多い。**
「毎日続ける」ことを狙うなら、スマホで使えないのは大きな制約になる。

ただし**急ぎではない。** 公開自体はパソコン向けのままでもできる。

---

## ⚠️ 着手前にオーナーに確認すること

> スマホ対応について、範囲を決めてください。
>
> **① どこまでやりますか**
> - **案A: 全画面をスマホでも使えるようにする** — 作業は大きい
> - **案B: 問題を解く流れだけ**（ステージ選択 → 問題 → リザルト） — 設定などは後回し
> - 案C: いまのまま（簡易表示）で公開し、様子を見てから
>
> **考えどころ:** Ferret は**コードを読む**アプリです。
> スマホの狭い画面でコードを読むのは、そもそも体験として厳しい面があります。
> 「移動中に軽く復習する」用途を狙うのか、
> 「腰を据えて取り組むのはパソコン」と割り切るのかで、かける労力が変わります。
>
> **おすすめは案B**です。まず問題を解けるようにして、
> 実際にスマホで使ってみてから範囲を広げるほうが無駄がありません。
>
> **② 回答の入力についてはどうしますか**
> スマホでは長い文章を打つのが大変です。
> いまは最低文字数の決まりがありますが、
> **スマホだけ緩めるかどうか**を決めてください。
> （緩めると採点の基準が端末によって変わるので、**個人的には緩めないことを勧めます**）

---

## 手順

1. 範囲を決める
2. ステージ選択（`app/stages/page.tsx` / `components/stage/StageMap.tsx`）
   - いまは横幅1024px以上で3列。狭いときの表示を作る
   - マップの蛇行の幅を狭い画面に合わせる
   - 連続日数などの情報の置き場所を決める
3. 問題画面（`app/problems/[id]/page.tsx` / `ProblemForm.tsx`）
   - **コードの枠が横に溢れないようにする**（横スクロールできるようにする）
   - 下に固定されている回答ボタンが、キーボードを出したときに隠れないようにする
4. リザルト画面（`app/result/[id]/ResultView.tsx`）
5. 実機またはブラウザの端末表示で確認する
6. `npm run build`

## 終わったと言える条件

- [ ] 範囲についてオーナーの判断を得ている
- [ ] 決めた範囲の画面が、幅375px（一般的なスマホ）で崩れずに使える
- [ ] **コードが画面から溢れない**（横スクロールできる）
- [ ] キーボードを出しても回答ボタンが押せる
- [ ] **パソコンでの見た目が変わっていない**
- [ ] `npm run build` が通る

---

## 注意

- **パソコン向けの表示を壊さないこと。** ここが一番起きやすい事故
- コードは折り返さないこと。折り返すと**行の対応が分からなくなり、読解の妨げになる**
- ステージマップは横位置を割合で計算している。狭い画面では丸が重なりやすい
