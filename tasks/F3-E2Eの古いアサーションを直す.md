## なぜ必要か

**3階層のテストのうち、一番外側が丸ごと死んでいる。**

単体・結合は 537件通っているが、これらは Supabase も OpenAI も差し替えた状態で動く。
**「ブラウザで実際に操作したら本当に動くのか」を見ているのは E2E だけ。**
ここが落ちたままだと、画面の作り替え（E1・E2・E5・E8 など）で
壊れても誰も気づけない。

もう1つ質の悪い問題がある。**落ちている理由が「見出しが見つからない」なので、
一見すると画面が壊れているように読める。** 実際は壊れていない。
このまま放置すると、次に E2E を回した人が
**自分の変更が壊したと思い込んで、無関係な場所を探し回ることになる。**

---

## 原因（調査済み・2つある）

**どちらも F1（`middleware.ts` → `proxy.ts` の移行）とは無関係。**
移行前のコードに戻して同じテストを走らせ、**まったく同じ落ち方をすることを確認済み。**

### ① アサーションがデザイン移植に追いついていない

`tests/e2e/auth.spec.ts:27` などが、ログイン画面に「ログイン」という**見出し**があることを
期待している。

```ts
await expect(page.getByRole("heading", { name: "ログイン" })).toBeVisible();
```

しかし `943345a`（モックのデザインを各画面へ移植する）で、
**ログイン画面の見出しは「おかえりなさい」に変わっている。**
「ログイン」は送信ボタンのラベルにしか残っていない。

同じ理由で E-103 の「ステージ選択」という見出しも、いまの画面にあるか確認が必要。

### ② `127.0.0.1` からの開発リソースが遮断されている

`playwright.config.ts:27` の `baseURL` は `http://127.0.0.1:3100`。
一方 Next.js 16 は、**`localhost` 以外から開発用リソースを取りに行くのを既定で止める。**
実行中このログが大量に出る。

```
⚠ Blocked cross-origin request to Next.js dev resource /_next/static/chunks/... from "127.0.0.1".
```

**JS が読み込めないのでハイドレーションが起きない。**
つまりログイン画面のフォームが動かず、ボタンを押しても何も起こらない。
①を直しても、こちらを直さないとログインを伴うテスト（E-103・E-104・E-105・E-130）は通らない。

## 手順

1. **②を先に直す。** ①だけ直しても、ログインを伴うテストは通らない
   - `playwright.config.ts` の `BASE_URL` を `http://localhost:${PORT}` にする（**こちらが軽い**）
   - または `next.config.ts` に `allowedDevOrigins: ['127.0.0.1']` を足す
   - **前者を推奨。** 本番の設定に手を入れずに済み、遮断そのものは開発時の安全機能として残る
2. `npm run test:e2e -- tests/e2e/auth.spec.ts` を回して、残る失敗を見る
3. **落ちたアサーションを、いまの画面の実際の文言に合わせる**
   - 画面を実測してから直すこと。推測で直すと今度は別の理由で落ちる
   - 「見出し」で取るか「ボタン」で取るかも、実際の DOM に合わせる
4. `auth.spec.ts` が通ったら、**残りの E2E も全部回す**
   （`display` / `scoring` / `stages` / `security`）。同じ理由で落ちている可能性が高い
5. `tests/e2e/テストケース.md` の状態列を実態に合わせる

### 原因は3つだった（票に書いてあったのは①だけ）

1. **①アサーションがデザイン移植（`943345a`）に追いついていない** — 票のとおり。ただし範囲は
   見出しだけでなく、**マップのアイコン・ポップオーバー・リザルトの点数表示**まで及んでいた
2. **②`baseURL` の `127.0.0.1` は、すでに `1116f81` で `localhost` に直っていた。**
   票の「`playwright.config.ts:27` が `127.0.0.1`」は**記述が古い**（票を書いた時点の main には入っていた修正）。
   念のため実測した: dev サーバーに `127.0.0.1` で入ると
   `Blocked cross-origin request` が **7件**、`localhost` では **0件**。
   遮断そのものは健在で、いまの設定で避けられている。**`next.config.ts` の `allowedDevOrigins` は不要。**
   通しの実行ログにも警告は1件も出ていない
3. **③シード問題（`order` 9000番台）が解放されず 404** — 票に無い分。
   E4 の申し送りが「全体を通すには選択が要る。E4 の範囲を超えるので別タスクに切る」と残していたもので、
   **これが認証以外の全テストを落としていた本体。**

### ③で選んだ方針とその理由

E4 が残した選択肢は「シードを先頭の `order` に置く」か「フィクスチャで毎回手前をクリアする」。
**後者にした。** 前者はマップの横位置が `XS[(order - 1) % 10]` で決まるため、
`order` を 1 未満にすると**添字が負になって描画が崩れる**。実コンテンツと番号を取り合う問題も残る。

`problems` フィクスチャが `clearPrecedingStages` を呼ぶようにした。副作用が2つ出た。

- **マップにクリア済みノードが実コンテンツの数だけ並ぶ。** よってノードの**個数を数えるテストは書けない**
  （`🔒 が problems.length - 1 個` のような書き方は、問題が100問に増えると必ず壊れる）。
  1つずつ状態を読む `stageState` を用意して置き換えた
- **下ごしらえの行が使いすぎ防止（1分10件）に当たって 429 になる。**
  `/api/score` は `user_attempts` の行数をそのまま数えるので、直前に10件入れると本体の採点が弾かれた。
  → **下ごしらえの行を48時間前の日付で入れる**ことで解決。
  解放判定は最高点だけを見るので結果は変わらず、「手前は以前クリアした」という状態のほうが実際に近い

### 状態の読み方（アプリを触らずに済ませた工夫）

マップのアイコンは SVG で、**読み上げ用の名前が付いていない**ので文字では引けない。
`aria-label` を足せばテストは素直になるが、票が「画面のコードを変えてテストに合わせない」と
定めているので触っていない（`StageMap.tsx` は E7・E8 の担当ファイルでもある）。
代わりに**振る舞い**で判定した。

| 状態 | 判定 |
|---|---|
| `locked` | ボタンが押せない（`disabled`） |
| `current` | 「スタート」の吹き出しが出ている |
| `cleared` | 押せるが現在地ではない（**消去法なので単体では弱い**） |

`cleared` が弱いぶん、境界のテスト（E-202・E-203・E-203b）は
**「次のノードが `current` になること」と対で**確かめている。こちらは消去法ではない。

**合否の文言は必ず見出し（h1）で引くこと。** 文字として引くと、Next.js の読み上げ用の領域
（遷移のたびに見出しの文字を複製する `role="alert"`）にも当たって2件になり、strict mode で落ちる。
E-410 が実際にこれで落ちた。

### テスト自身の欠陥を2件見つけた（アサーションの古さとは別）

- **E-261 は成立していなかった。** スタブが返す引用（`EVIDENCE_REAL`）が、この設問で使う
  短い回答の中に**実在しない**。引用照合（`compose.ts`）は本物が動くので full が必ず partial に落ち、
  何を直しても不合格になる。回答に実在する引用を渡すようにして 70点・クリアで固定した。
  **スタブを使っていても採点の中身は本物**、という前提がここで効く
- **E-413 は何も検査していなかった。** `expect(new URL(page.url()).host).toBe(new URL(page.url()).host)` と
  自分自身を比べていた（常に真）。`baseURL` のホストと比べるように直した
