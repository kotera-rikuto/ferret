## まず事実として（ここを誤解すると無駄な作業をします）

### ① いま知らないのは当たり前

**公開したのが 2026-08-22 で、まだ数日です。**

AI は「学習した時点までの知識」と「その場で検索した結果」の2つで答えます。
**数日前に公開されたサイトが学習データに入っていることはありえません。**

つまり打ち手は2つに分かれます。

| | 効くまで | 何をするか |

## 手順

1. 上の3点を決める
2. **構造化データ（JSON-LD）を入れる**
   - `app/layout.tsx` か LP に `application/ld+json` を置く
   - `schema.org` の `WebSite` / `EducationalOrganization` / `Course` あたり
   - **書く内容:** サービス名・一文の説明・URL・言語（日本語）・無料で始められること
   - ⚠️ **嘘を書かないこと。** 価格や実績を書くと、AI がそれを事実として答えます
3. **`llms.txt` を置く**（`public/llms.txt`）
   - AI 向けにサイトの説明を平文で置く新しめの慣行
   - **何のサービスか / 誰向けか / 主な画面 / 使い方**を数行で
   - **まだ広く守られている決まりではない**ので、費用対効果は「置くだけ安い」程度
4. **説明文を1か所にまとめる**
   - いま `lib/seo/site.ts` に説明文がある。**JSON-LD と llms.txt も同じ出どころから読む**
   - **バラバラに書くと、AI が矛盾した説明を拾います**
5. 確認する
   - Google のリッチリザルトテストなどで JSON-LD が読めるか
   - `https://ferretcode.com/llms.txt` が開けるか
6. **記録を残す** — 「いつ何をしたか」と「その時点で AI が何と答えたか」
7. `npm run build`

**説明文の出どころを1本にした**（票の手順4）。`SITE_DESCRIPTION` → メタ情報・JSON-LD・`llms.txt`、
`SITE_FACTS` → `llms.txt` の本文と JSON-LD の `featureList`、`CHAPTERS` と `CLEAR_THRESHOLD` → 問数・章数・クリア点。
**数字は定数から導いてある**ので、章が増えた日に説明だけ古くなることがない。

**嘘を書かない仕掛け**

- **価格は `SITE_IS_FREE` 1か所から出る。** 有料化（D2）の日にここを `false` にすると、
  JSON-LD から `offers` が項目ごと消える。**U-894 がその連動を検査する** ──
  放置すると「有料化した後も AI が無料だと答える」形で外に出るが、
  自分の画面は正しい価格を出しているので**サイトを見ても気づけない**
- **U-895** が `aggregateRating` / `reviewCount` などの実績系の項目を弾く（利用者数・評価は名乗らない）
- **U-897** が `llms.txt` にログインが要る画面のURLを書かせない（`CRAWL_DISALLOW` と突き合わせ）
- **U-899** が読解型6種を DB の CHECK 制約（`20260812010000_scoring_v3.sql`）と一字単位で突き合わせる
- **U-900** が「AI のクローラーを名指しで塞がない」という②の判断を固定する
- **利用の許諾は書かなかった。** 「学習・引用に使ってよい」は権利の許諾にあたり、
  **利用規約 第8条（禁止事項）・第9条（権利の帰属）── 問題文・解説・コード例の複製と再配布の禁止 ── と正面から食い違う。**
  `llms.txt` に書いたのは「拒否していない」という事実だけ
