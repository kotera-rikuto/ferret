## なぜこの形なら安全か（**当初の最大の懸念は消えている**）

**このタスクは元々「共有はRLS方針に穴を開ける作業になる」ことが最大の論点だった。画像だけにしたことで構造的に消えた。**

- **公開URLを作らない。** 画像を返す経路は**ログイン必須で、自分の回答の行しか読まない**
- つまり `user_attempts` は **「本人だけが読める・誰も書けない」のまま**。書き込みポリシーは0件のまま
- **「取り消せるようにする」も不要になった** ── 公開しているデータが無いので、取り消す対象が存在しない。
  SNSに貼った画像を消すのは本人の投稿削除であって、こちらの機能ではない

> **この段落は消さないこと。** 後から「やっぱり公開ページも」となった時点で、
> 推測できないURL・取り消し・公開範囲の3点が**全部まとめて戻ってくる。**
> いま要らないのは「画像だけ」を選んだからであって、共有一般が安全だからではない。

## ⚠️ 落とし穴1 ── フォントに問題名の漢字が入っていない（**実測済み**）

**106件のタイトルのうち85件が豆腐（□）で焼かれる。**足りない漢字は126種（2026-09-11 実測）。

原因: `assets/fonts/MPLUSRounded1c-Bold.subset.ttf` は
**`lib/seo/site.ts` に出てくる字＋英数記号＋かな**だけを切り出したもの（`design/og/subset-font.py`）。
**問題タイトルはDBにあるので、切り出しの対象に入っていない。**

`next/og`（satori）はフォントのバイト列に無い字を1文字も描けない。しかも
**エラーにならず豆腐で焼かれる**ので、SNSに流れてから気づくことになる。

### 対処の候補（全部その場で作って実測した）

| 案 | 大きさ | 問題が増えたとき |
|---|---|---|
| A. 足りない126字を足す | 271 KB | **1問足すたびに壊れる。** タイトルはDBにあるのでビルド時に気づけない |
| B. CJK漢字を全部入れる | 2,786 KB | ほぼ壊れない。①②や記号など漢字以外は依然抜ける |
| **C. フォントを丸ごと同梱** | **3,460 KB** | **二度と壊れない** |

**推奨は C。** 理由は3つ:

1. **このファイルはブラウザに配られない。** サーバーが画像を描くときに読むだけなので、利用者の通信量は1バイトも増えない
2. **豆腐は取り返しがつかない。** 他人のタイムラインに出て、SNS側にキャッシュもされる
3. **問題は今後も足す。** A が前提にしている「再生成を忘れない」は、忘れたときに何も起きないので必ず忘れる

- **LP用の 186KB の切り出し（`app/opengraph-image.tsx`）はそのまま残す。**
  あちらは文言がコードにあり、ビルド時に1回読むだけで、U-845 の検査も効いている。
  **共有カードだけが丸ごとのフォントを読む**形にする
- **どの案を採っても、`npm run test:db` に「全タイトルの字がフォントに入っているか」の検査を足すこと。**
  **問題を足したときに気づける場所はここしかない。**
  読み方は `tests/unit/og-image.test.ts` の `codepointsInFont` をそのまま使い、対象をDBのタイトルに変える

## 実装の手順

### 1. 画像を返す経路

`app/api/share/[attemptId]/route.tsx`（**`.tsx`。JSX を書く**）

- **`export const runtime = "nodejs"` を明示。** フォントとマスコットをディスクから読む
- `auth.getUser()` で本人確認。無ければ **401**
- **`user_attempts` は session クライアントで1行だけ読む。**
  **`admin` を使わないこと** ── RLS が壊れたときに「他人の点数の画像が出る」側へ倒れる。
  session なら「自分の行が読めなくなる＝画像が出ない」側に倒れる（`app/result/[id]/page.tsx` の XP 取得と同じ理由）
- 条件: `is_provisional = false` かつ `total_score >= CLEAR_THRESHOLD`。満たさなければ **404**
  （クリアした回だけ・オーナー判断。**しきい値は `lib/ai/compose.ts` から読む。数字を書かない**）
- **タイトルは `problems` から admin クライアント + カラム明示で `title` だけ。**
  `problems` は RLS ポリシー0件なので session では読めない（CLAUDE.md「サーバー経由・カラム明示」）。
  **`model_answer` を select に入れないこと**
- `ImageResponse` で 1200×630。配色・マスコット・下端の帯は `app/opengraph-image.tsx` からそのまま持ってくる
- **`Cache-Control: private, no-store`。** 個人の点数なので途中のキャッシュに残さない
- **`proxy.ts` の matcher は触らない。** あれは**画面**を列挙するもので、APIは自前で `getUser()` する。
  `CRAWL_DISALLOW` も**触らない**（`/api` が既に入っている）。片方だけ足すと U-836 が落ちる
- `isCrossSiteRequest` / `hasJsonContentType` は**不要**（あれは新しい **POST** API の決まり。これは GET）。
  ただし**他サイトから `<img src>` で埋められてもCookieが飛ばないこと**は確認しておく
  （`lib/supabase/cookies.ts` は `sameSite` を明示していない＝ブラウザ既定の Lax）

### 2. 画像の中身

- 「クリア！」＋ 点数（`85点`）
- 問題名
- `SITE_NAME` ＋ マスコット
- **`ferretcode.com` を絵の中に焼き込む。** 画像だけが流れたときに辿り着ける手掛かりはこれしかない
- ⚠️ **コード・模範解答・回答文を入れない**（`app/opengraph-image.tsx` の注意書きと同じ。答えがタイムラインに載る）
- ⚠️ **端は切られる。大事なものを外周60px以内に置かない**
- ⚠️ **暗いテーマは作らない。** 貼られた先の設定は分からないので1つに決める（既存カードと同じ判断）

### 3. リザルト画面の導線

`app/result/[id]/ResultView.tsx`

- **クリアの分岐にだけ足す**（不合格側には足さない）
- 置き場所: 主ボタン「つぎのステージへ」は**1本のまま**。
  その下のテキストリンクの行（「もう一度挑む」「ふりかえる」）に並べるか、主ボタンの直下に控えめに1本
  - ⚠️ **末尾に置かない。** 異議申し立ての行より下は読まれない
  - ⚠️ **説明文を足さない。** ボタンの文言だけで足りる
  - ⚠️ **迷ったら小さく畳む**（`<details>` で足りるなら JavaScript を足さない）
- 開いたら出るもの: 画像 ＋「画像を保存」＋「Xに投稿する」
  - ⚠️ **Xに画像を自動で添付する方法は存在しない。** 投稿画面に入るのは本文だけで、
    画像は本人が保存して手で添付する。**「保存 → 投稿」の順に見える並びにすること**
- Xの本文は **`lib/seo/site.ts` に定数で置く**（画面に出る文言は site.ts から出す・C12）。
  `https://x.com/intent/post?text=...`
  - ⚠️ 本文にもNGワードを入れない
  - URL は `siteOrigin()`。**ローカルとプレビューでは `null` になる**
    （`NEXT_PUBLIC_APP_URL` は本番だけ・C5）。**null のときの振る舞いを決めること**

**直したこと**

**判断の理由**

- **置き場所は「褒められた直後」。** 人に見せたくなるのはメモを読んだ瞬間で、

- **主ボタンと色で競合させない。** 「つぎのステージへ」がブランド色の塗りなので、
  カードの主役は `ink` の塗りにした（X の見た目にも寄る）。
  **同じ橙を2つ並べると、どちらへ進めばいいのか分からなくなる**
- **並びは「画像を保存 → X に投稿する」のまま。** X に画像を自動添付する方法は無く、
  先に保存しないと絵の無い投稿になる。読む順がそのまま手順になっている
- **`loading="lazy"` は畳むのをやめた後も残した。** カードはたいてい画面の外から始まるので、
  そこまで来ない人のぶんは描かずに済む（絵は1枚ごとにサーバーで描いている）

カードの地がページの地より沈んでいること（明 `#f6efdd` / 暗 `#100c06`）、
