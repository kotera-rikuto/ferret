## 何をするか

スマホで開いたときの3つの不具合を直す。**E8 で「アプリを進めるのに支障が出るところ」だけを直したので、その先が残っている。**

### ① 続けた日数・経験値などが表示されない

いま右側の情報パネル（レベル / つづけた日数 / すすみぐあい）は
**画面幅 1024px 未満で丸ごと消える**作りになっている（`app/stages/page.tsx` の `hidden lg:flex`）。

スマホだと**継続の手応えが一切見えない。** 連続日数はこのジャンルの継続率の本体なので、消えているのは痛い。

### ② メモ欄が下にあって使いにくい

コードを読みながら書くものなのに、**回答欄より下にある**ので、
コードとメモを同時に見られない。狭い画面では特に往復が増える。

### ③ 画面が安定しない

読み込み直後に**要素の位置がガタッと動く。** 何が動いているかは着手時に実測して特定すること
（章バナー・マップの現在地への自動スクロール・テーマの初期化スクリプトが候補）。

---

## なぜ必要か

**このジャンルのアプリは移動中や隙間時間に使われる。**
「毎日続ける」を狙っている以上、スマホで手応えが見えないのは continuity の設計そのものが効かない。

③は特に印象を損なう。**開いた瞬間に画面が跳ねるアプリは「雑に作られている」と受け取られる。**

### 2026-08-22 ── 実装（幅375px と 320px で実測しながら）

**オーナー判断:** ①②は個別に選ばず、**「基本的にデスクトップ版を縮小した感じ」**という方針で決まった。
そのうえで名指しの指示が2つ。**メモはコードでも答案でも使えるようにする**、
**タイトル画面はアプリの説明とキャラクターを並べる（デスクトップと同じ配置）**。
それ以外で「デスクトップに揃えるべき」と判断したものは自律的に実装してよい、という委任も受けている。

---

#### ③ の原因は2つあった。どちらも実測で特定した

**測り方。** `layout-shift`（CLS）では**何も出なかった**（0.0001）。
起動時の `scrollToCurrent` によるスクロールと同じフレームで動くので、ブラウザが
「スクロールによる移動」として除外してしまう。**CPU を 1/8 に絞って rAF ごとに
文書の高さを記録する**ほうに切り替えたら、はっきり出た。

**a. 行の高さを JS で選んでいた（これが本体）**

```
t=78ms   docH=21,069  節1の高さ=604   ← サーバーが返した配置（ROW_H=180）
t=985ms  docH=24,925  節1の高さ=692   ← ハイドレーション後に詰め直し（224）
```

**約900ms のあいだ 180 の配置が見えたまま、そのあと全ノードが動いて文書が 3,856px（+18%）伸びる。**
E8 は「起動時のスクロールに紛れる」と書いていたが、**紛れていなかった。**

E8 が JS を選んだ理由は「行の高さが SVG の `y1` / `y2` にも入り、幾何属性はメディアクエリの対象にならない」。
これは正しいが、**幾何属性を使わずに済ませられる。**

- 行の高さを CSS 変数にした（`[--row-h:224px] lg:[--row-h:180px]`）。
  節の高さとノードの縦位置は `calc(var(--row-h) * n + ...)` で書ける
- 道は **1区間 = 入れ物の div 1つ + 線1本**に分けた。入れ物の上下端を丸の中心に合わせておけば、
  線は入れ物の中で **0% → 100%** を結ぶだけでよく、px の座標を持たなくて済む。
  横位置は入れ物が `inset-x-0`（節と同じ幅）なので、これまでと同じ割合がそのまま使える
- **章を跨ぐ1本だけは長さが行の高さに依らない。** 下端は次の節の先頭ノード、上端はこの節の
  最下段の丸の中心なので、引き算すると行の高さが打ち消えて `PAD_TOP + NODE_H + CHAPTER_GAP - CIRCLE_MID` になる

結果、**サーバーが返した HTML のまま幅だけで正しい配置が出る。** 実測は1フレーム目から `docH=25,029` の1値のみ。
`useNarrow` / `useSyncExternalStore` / `matchMedia` は消え、`scrollToCurrent` の effect も1回で済むようになった
（`rowH` を依存に入れて2回走らせる必要が無くなった）。

⚠️ **Tailwind は class 名を文字として探す。** `[--row-h:224px]` をテンプレートリテラルで組み立てると
**宣言そのものが CSS に出力されず、`calc()` が全部無効になってマップが1点に潰れる。**
リテラルで持つこと（`ROW_H_CLASS`）。検査は `tests/unit/stage-map.test.ts` の U-823。

**b. 章バナーの高さが 81px ⇄ 65px で伸び縮みしていた**

章の番号（`第N章`）は `chapterOf` が null を返す order で消える。バナーは貼り付いているので、
**その章に差しかかった瞬間に下のマップ全体が 16px 跳ねる。**
`min-h-11`（44px = `py-4` と `border-b-5` を除いた2行ぶん）で高さを固定した。
空の行を置くのではなく箱の高さを決めたのは、番号が無いときに「説明のつかない空白の行」を作らないため。

**これがパソコン側で唯一変わる点。** 該当するのは **`order = 999` の1問だけ**
（`const と let ─ 再代入できる箱・できない箱`。動作確認用でマップの最上部にいる）。
その節を見ているときだけバナーが 16px 高くなる。**跳ねを残すより高さを固定するほうを採った。**

---

#### ① 数字は画面の上に貼り付けた（`h-15` = 60px の帯・3枚のチップ）

票の案Aは「画面の上に横1列」だったが、**貼らずに上に置くと一度も目に入らない。**
マップは起動時に現在地までスクロールするので、375px の実測では
ページの 124〜24,000px の位置に着地する ── 上端の帯は最初から画面の外にある。

- レベル（数字 + 細いバー）／つづけた日数（ほのお + 日数）／すすみぐあい（✓ + クリア数 + 細いバー）
- **0日のときの言い換えは右の `aside` と同じ文言**（「きょう解くと1日目」）。狭いので2行に折るだけ
- 章バナーは帯の下に貼り付く（`top-16 lg:top-4`）。
  **`scrollToCurrent` は貼り付く位置を `getComputedStyle(banner).top` から読むようにした** ──
  ここに数字を書き写すと、帯の高さを変えた日に着地の計算だけが古い値で残る（`STICKY_TOP` 定数は削除）
- **Pro の案内カードは狭い画面に出していない。** 決済が未実装で押せないボタンなので、
  25,000px のマップの上か下に置いても誰も見ず、貼るには縦が足りない

#### ② メモは画面の上に貼り付く開閉できる帯にした

指示は「コードでも答案でも使えるように」。パソコンでは横の列を `sticky` にして満たしているが、
狭い画面には横に並べる幅が無い。**縦に積むと置いた場所の片方でしか使えない** ──
2026-08-21 までは回答欄の下にあり、コードを読んでいる位置からメモまで 500px 下だった（375px で実測）。

ヘッダー（70px）の真下に貼り付けた。**閉じている間の縦の代償は 44px**、開くと 172px（375px で実測）。
`order-first` は見た目だけ先頭に出すためで、**DOM の順は回答欄より後ろのまま**
（回答欄から Tab を押したときに当たるのがメモにならない。E-455 で直した導線）。

**既定を「閉じた状態」に変えた。** それまでは保存済みメモがあれば開いて出していたが、
上に貼り付けたことで**メモの有無で最初の描画が 128px ずれる**ようになった ──
`localStorage` はサーバーから見えないので、開くかどうかが決まるのはハイドレーションの後で、
その瞬間にコードが下へ飛ぶ（③ で直したのと同じ種類の跳ね）。
代わりに、書いたものがあることは帯の中の小さな点で知らせる。

#### 「デスクトップに揃える」と判断して自律的に直したもの

- **タイトル画面を横並びにした**（名指しの指示）。`flex-col` → `flex-row` にして、
  マスコットと文字を小さくする。**幅360px 未満だけマスコットをさらに小さくする**
  （`w-20 min-[360px]:w-32`）── 320px では文字の列が 176px しか残らず、
  「他人のコードが読める、」が 176px ちょうどで折り返していた
- **狭い画面に行き先（ステージ / ふりかえり / せってい）を出した。**
  **スマホからは「ふりかえり」と「せってい」に辿る道が1本も無かった** ──
  パソコンでは左のナビにあるので気づきにくい。ふりかえり（E1）は解いたあとに見返す機能なので、
  無いと機能そのものが届いていない。4画面で同じものを出すので
  `components/layout/MobileHeader.tsx` に切り出した（それまでは4か所に同じ markup があった）。
  **文字は付けない**（375px にロゴとログアウトを足して収まらない）。読み上げ用の名前は `aria-label`
- **設問のフェレットを狭い画面でも出した。** `hidden sm:block` で消していたが、
  問いかけの形はこの画面の手がかりそのもの（一方的な指示文に見えないための作り）で、
  消すとスマホだけ素の指示文になる。48px にして吹き出しの向きも残した

#### 揃えなかったもの（理由つき）

- **回答ボタンの固定は復活させない。** E8 が狭い画面で固定をやめたのは
  「仮想キーボードが出ると `fixed` の要素がその裏に入る」からで、揃えると回答が送れなくなる
- **問題画面のタイトルの1行切り詰めも戻さない**（E8。折り返すと帯だけで画面の 1/7 を使う）

---

#### パソコン側が動いていないことの確かめ方

E8 と同じやり方に、行の高さの作り替えに合わせた比較を足した。

- **スクリーンショットのバイト単位比較**（幅1440 / 1024。`animations: "disabled"` で撮る）:
  タイトル・ログイン・新規登録・問題・ふりかえり・せってい **すべて一致**
- **マップは幾何を書き出して比較**（吹き出しと輪の動きで画像比較ができないため）。
  **マップの入れ物を原点にした相対座標**で出す ── ページ原点だとバナーの高さの差（③-b）が
  全ノードに乗ってしまい、道の付け替えを見られない。
  幅1440 / 1024 / 375 の3つで、**ノード103個・ラベル103個・節15個・道の端点102本すべてが一致**
  （`x1`/`y1`/`x2`/`y2` は `getScreenCTM()` で画面座標に直して突き合わせた）。
  マップ全体の高さも一致（1440/1024 で 20,788px、375 で 24,660px）
- ステージ画面のスクリーンショットだけ **+16px** で、内訳は③-b のバナー1か所

  ほうが効く**と考えられるので、そちら側で決めるのが筋。D1 の続きとして起票するのがよい

  **このタスクでも直していない。** `scrollToCurrent` に手は入れたが、直すのは別タスクの範囲
