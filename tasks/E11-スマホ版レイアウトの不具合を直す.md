# E11. スマホ版のレイアウトの不具合を直す

**種別:** 実装（見た目の不具合修正）
**規模:** 中
**前提として終わっていること:** なし（**E8「スマホ対応」の続き**）

> ### ⚠️ 同時進行の注意
> **触る範囲が広いので、他の画面系タスクと同時に進めないこと。**
> `app/stages/page.tsx` `app/problems/[id]/page.tsx` `MemoPad.tsx` `components/stage/StageMap.tsx` を触る。
> **着手前に `main` を取り込むこと。**

**先に読むもの**
- `tasked/E8-スマホ対応.md` の **作業記録**（**必読。** 前回どこまでやって、何を意図的に残したかが書いてある）
- `design/stages-mock.html`（モバイル版レイアウトの案）

---

## 何をするか

スマホで開いたときの3つの不具合を直す。**E8 で「アプリを進めるのに支障が出るところ」だけを直したので、その先が残っている。**

### ① 続けた日数・経験値などが表示されない

いま右側の情報パネル（レベル / つづけた日数 / すすみぐあい）は
**画面幅 1024px 未満で丸ごと消える**作りになっている（`app/stages/page.tsx` の `hidden lg:flex`）。

スマホだと**継続の手応えが一切見えない。** 連続日数はこのジャンルの継続率の本体なので、消えているのは痛い。

### ② メモ欄が下にあって使いにくい

コードを読みながら書くものなのに、**回答欄より下にある**ので、
コードとメモを同時に見られない。狭い画面では特に往復が増える。

### ③ 画面が安定しない

読み込み直後に**要素の位置がガタッと動く。** 何が動いているかは着手時に実測して特定すること
（章バナー・マップの現在地への自動スクロール・テーマの初期化スクリプトが候補）。

---

## なぜ必要か

**このジャンルのアプリは移動中や隙間時間に使われる。**
「毎日続ける」を狙っている以上、スマホで手応えが見えないのは continuity の設計そのものが効かない。

③は特に印象を損なう。**開いた瞬間に画面が跳ねるアプリは「雑に作られている」と受け取られる。**

---

## ⚠️ オーナーに確認すること

> スマホでの見せ方を決めてください。
>
> **① レベル・つづけた日数・すすみぐあいを、狭い画面のどこに置きますか**
> - **案A: 画面の上に横1列で小さく並べる**（おすすめ）
>   3つの数字だけを1行に。マップの上に置くので、開いた瞬間に目に入ります
> - 案B: 開閉できるパネルにする
>   場所を取りませんが、たたんでいる間は見えないので、continuity の効果が薄れます
> - 案C: 下に固定して常に出す
>   常に見えますが、**マップを表示できる高さが削られます**
>
> **おすすめは案A**です。「続いている」ことは開いた瞬間に見えるのが効くためで、
> 数字3つなら1行に収まります。
>
> **② メモ欄をどこに置きますか**
> - **案A: コードのすぐ下、回答欄の上**（おすすめ）— 読みながら書く順番と一致します
> - 案B: 開閉ボタンで出す — 画面は広く使えますが、開く操作が1つ増えます
> - 案C: いまのまま（回答欄の下）
>
> **③ 画面の跳ねについて**
> 原因を特定したら報告します。**直し方が「起動時に現在地へスクロールする動きをやめる」に
> なる場合は、体験が変わるので判断をもらいます**（いまは開いた瞬間に現在のステージが
> 画面の中央に来るようになっています）。

---

## 手順

1. **まず実測する。** 幅375px（一般的なスマホ）で3つの症状を再現し、
   ③については**何がどれだけ動いているか**を記録する（ブラウザの開発者ツールで足りる）
2. 上の①②を確認して決める
3. ①を実装 — `app/stages/page.tsx` の `aside` を、狭い画面用の並びに出し分ける
   - **`lg` 以上の見た目を変えないこと**
4. ②を実装 — `app/problems/[id]/page.tsx` の `MemoPad` の位置
   - ⚠️ **`MemoPad.tsx` の `SIDE_BY_SIDE` と問題画面のしきい値は対になっている。**
     片方だけ動かすとコードの折り返しが変わる（E8 の作業記録に明記されている）
5. ③を実装
6. 幅375px で全画面を確認する
7. `npm test` `npm run test:e2e`（モバイル設定が入っている）`npm run build`

## 注意

- **パソコンでの見た目を壊さないこと。** E8 でも同じ注意が書かれている
- コードは折り返さないこと（行の対応が分からなくなり読解の妨げになる）
- 数字を出すときは**「あなたは○○レベル」という言い方をしない**（UXルール。`app/stages/page.tsx` にコメントあり）
- 0日のときは「きょう解くと1日目」と出す既存の扱いを踏襲すること（0を罰に見せない）
