# C1. 確認メールが実際に届くようにする（Resend）

**種別:** 実装 + 外部サービス設定
**規模:** 中
**前提として終わっていること:** なし
**このタスクが終わらないと着手できないもの:** C3 のうちメールアドレス変更、C5（本番デプロイ）

> ### ⚠️ 同時進行の注意
> **同時に進めてはいけない相手は無い。** ただし `supabase/config.toml` は
> C3・C4・C5 も触る。**着手前に `main` を取り込むこと。**

**先に読むもの**
- `ideas/セキュリティ_残課題.md` の §1（メール確認まわりの注意）

---

## 何をするか

**新規登録したときに届く確認メールを、ちゃんと届くようにする。**

いま新規登録すると「メールアドレスの確認」が必須になっている。
ところがメールの送信は Supabase に最初から付いている簡易的な機能を使っていて、
**1時間に数通しか送れない。** このまま公開すると、**新しく登録した人にメールが届かず、
誰もアカウントを作れない。**

Resend というメール送信サービスに切り替える。

---

## なぜ必要か

**これが無いと、公開しても誰も使えない。** 公開前に必須の項目。

なお、メール確認そのものを外す（確認なしで使えるようにする）という選択肢は**取らない。**
確認を外すと存在しないメールアドレスで無限にアカウントを作れてしまい、
**アカウント単位でかけている採点の回数制限が意味を失う**ため。

---

## ⚠️ 着手前にオーナーに確認すること

> メール送信の設定に、送信元のドメイン（メールアドレスの `@` より後ろ）が必要です。
>
> - **独自ドメインが決まっている場合:** そのドメインで設定します。
>   ドメインの管理画面で、送信を許可する設定（3行ほどの登録）が必要になります
> - **まだ決まっていない場合:** Resend が用意しているお試し用のドメインで先に動かせます。
>   ただし**お試し用は自分宛にしか送れない**ので、公開前に必ず独自ドメインへ切り替えが必要です
>
> どちらで進めますか。
> また、送信元の表示名（例:「Ferret」）と、返信先にするアドレスがあれば教えてください。

---

## 手順

1. Resend でアカウントを作り、APIキーを発行する
2. **`.env.local` の `RESEND_API_KEY` に値を入れる**
   - ⚠️ **いまキー名だけあって値が空。** 一部のドキュメントに「用意済み」と書いてあるが誤り
3. 送信元ドメインを Resend に登録する（上の確認で決めた方）
4. Supabase の管理画面で SMTP の設定をする
   - Project Settings → Authentication → SMTP Settings
   - Resend が案内する接続情報を入れる
5. **確認メールの文面を日本語にする**
   - Supabase の管理画面 → Authentication → Email Templates
   - **ネガティブな言葉を使わないこと**（`CLAUDE.md` の文言ルール）
6. 実際に新しいメールアドレスで登録して、**メールが届き、リンクを押すとログインできる**ことを確認
7. 迷惑メールに入らないかも確認する

## 触る場所

| 場所 | 何をするか |
|---|---|
| Resend の管理画面 | アカウント・APIキー・ドメイン登録 |
| `.env.local` | `RESEND_API_KEY` に値を入れる |
| Supabase 管理画面（SMTP Settings） | 送信の接続設定 |
| Supabase 管理画面（Email Templates） | 文面の日本語化 |
| `.env.local.example` | 必要なら注記を追記 |

**アプリのコードは基本的に変更しない。** メール送信は Supabase 側で行われるため。

## 終わったと言える条件

- [ ] 新しいメールアドレスで登録すると確認メールが届く
- [ ] メール内のリンクを押すとログインできる
- [ ] 文面が日本語で、禁止されている言葉を含まない
- [ ] 迷惑メールに振り分けられない
- [ ] `RESEND_API_KEY` に値が入っている
- [ ] `ideas/セキュリティ_残課題.md` と `残タスク.md` の「用意済み」という誤記が直っている

---

## 注意

⚠️ **`supabase config push` を実行しないこと。**

設定ファイル（`supabase/config.toml`）に本番の設定を送り込むコマンドだが、
**いま実行すると本番の確認メールのリンクが `localhost` を指すようになる。**
ファイル内の `site_url` がまだ開発用のままのため。一部だけ送る方法はない。

このタスクでは**管理画面から設定すること。**
設定ファイルで管理できるようにするのは C5（本番デプロイ）で本番URLを決めてから。
