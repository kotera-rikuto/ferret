## 何をするか

**新規登録したときに届く確認メールを、ちゃんと届くようにする。**

いま新規登録すると「メールアドレスの確認」が必須になっている。
ところがメールの送信は Supabase に最初から付いている簡易的な機能を使っていて、
**1時間に数通しか送れない。** このまま公開すると、**新しく登録した人にメールが届かず、
誰もアカウントを作れない。**

Resend というメール送信サービスに切り替える。

---

## なぜ必要か

**これが無いと、公開しても誰も使えない。** 公開前に必須の項目。

なお、メール確認そのものを外す（確認なしで使えるようにする）という選択肢は**取らない。**
確認を外すと存在しないメールアドレスで無限にアカウントを作れてしまい、
**アカウント単位でかけている採点の回数制限が意味を失う**ため。

---

## ⚠️ 着手前にオーナーに確認すること

> メール送信の設定に、送信元のドメイン（メールアドレスの `@` より後ろ）が必要です。
>
> - **独自ドメインが決まっている場合:** そのドメインで設定します。
>   ドメインの管理画面で、送信を許可する設定（3行ほどの登録）が必要になります
> - **まだ決まっていない場合:** Resend が用意しているお試し用のドメインで先に動かせます。
>   ただし**お試し用は自分宛にしか送れない**ので、公開前に必ず独自ドメインへ切り替えが必要です
>
> どちらで進めますか。
> また、送信元の表示名（例:「Ferret」）と、返信先にするアドレスがあれば教えてください。

---

## 手順

1. Resend でアカウントを作り、APIキーを発行する
2. **`.env.local` の `RESEND_API_KEY` に値を入れる**
   - ⚠️ **いまキー名だけあって値が空。** 一部のドキュメントに「用意済み」と書いてあるが誤り
3. 送信元ドメインを Resend に登録する（上の確認で決めた方）
4. Supabase の管理画面で SMTP の設定をする
   - Project Settings → Authentication → SMTP Settings
   - Resend が案内する接続情報を入れる
5. **確認メールの文面を日本語にする**
   - Supabase の管理画面 → Authentication → Email Templates
   - **ネガティブな言葉を使わないこと**（`CLAUDE.md` の文言ルール）
6. 実際に新しいメールアドレスで登録して、**メールが届き、リンクを押すとログインできる**ことを確認
7. 迷惑メールに入らないかも確認する

### なぜリンクの形を変えたか

Supabase の既定のリンク（`{{ .ConfirmationURL }}`）は、**登録したブラウザに残る控え**を使って
ログインを成立させる仕組みに繋がっている。つまり**パソコンで登録してスマホでメールを開くと、
控えが無いのでログインできない。** ユーザーには理由の分からないエラー画面が出る。

`{{ .TokenHash }}` 方式はリンクそのものに確認用の値が入っているので、どの端末で開いても通る。
受け取り側（`app/auth/callback/route.ts`）は**既存の `code` 方式を残したまま**、
もう1つの受け取り方として足した。OAuth（Google / GitHub）は今後も `code` 方式を使う。

---

### ⚠️ タスク票に無かった落とし穴（重要）

**Resend に切り替えるだけでは、まだ1時間に2通しか送れない。**

`supabase/config.toml:227` の `email_sent = 2` は管理画面の既定値でもあり、コメントに
`Requires auth.email.smtp to be enabled` と書かれている。つまり
**この上限は独自SMTPを有効にしないと変更すらできない。**
SMTP の設定と**同時に**この上限を上げないと、送信元が Resend になっただけで症状は今と変わらない
（公開後、同時刻に登録した3人目からメールが届かない）。手順 4 がこれに当たる。

### 残っている手順（管理画面での作業）

**1. Resend でアカウントを作り、APIキーを発行する**

`https://resend.com` で登録 → 左メニュー **API Keys** → **Create API Key**。
権限は **Sending access** だけでよい（ドメイン管理の権限は不要）。
**値が表示されるのは1回だけ。** その場でコピーする。

**2. `.env.local` の `RESEND_API_KEY` に貼る**

`re_` で始まる文字列。**アプリはこの値を読まない**（メールを送るのは Supabase）。
ここに置くのは控えで、実際に使われるのは次の手順で Supabase に入れたほうである。

**3. Supabase に SMTP を設定する**

管理画面 → **Project Settings → Authentication → SMTP Settings** → **Enable Custom SMTP** を ON。

| 欄 | 値 |
|---|---|
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | 手順1のAPIキー |
| Sender email | `onboarding@resend.dev` |
| Sender name | `Ferret` |

（出典: Resend 公式ドキュメント `resend.com/docs/send-with-smtp`。465 は SSL/TLS。
587 でも動くが、その場合は平文で繋いでから暗号化に切り替わる形になる）

**4. メール送信の上限を上げる**（⚠️ 上の「落とし穴」。手順3と同時に必須）

管理画面 → **Authentication → Rate Limits** → **Emails sent per hour** を `2` から上げる。
**30 程度で十分**（Resend 側の無料枠は1日100通・月3,000通なので、その内側に収まる）。

**5. Site URL を確認する**

管理画面 → **Authentication → URL Configuration → Site URL**。
確認メールのリンクはここを基点に組み立てられる（`{{ .SiteURL }}`）。
**開発中は `http://localhost:3000` になっていること。**
`127.0.0.1` や別のポートだと、リンクが開発サーバーと違う場所を指す。

**6. 文面を貼る**

管理画面 → **Authentication → Emails → Confirm signup**。

- 件名: `Ferret のメールアドレス確認`
- 本文: **`supabase/templates/confirm-signup.html` の中身をそのまま貼る**
  （先頭の `<!-- ... -->` のコメントは貼らなくてよい）

貼ったら、以降**文面を変えるときは必ず両方**を直す（管理画面は Git で追えない）。

**7. 実際に登録して確かめる**

```bash
npm run dev
```

`/register` を開き、**Resend に登録したご自身のメールアドレス**で登録する。
（公式ドキュメントは「送信にはドメインの追加と認証が必要」と書いており、
**他人のアドレスに届くようになるのは独自ドメインを認証してから。** それまでは自分宛で確認する）

- [ ] メールが届く（**迷惑メールフォルダも見る**）
- [ ] 差出人が `Ferret` になっている
- [ ] 文面が日本語で、禁止されている言葉が無い
- [ ] **同じブラウザ**でリンクを押す → `/stages` に入れる
- [ ] **スマホなど別の端末**でリンクを開く → `/stages` に入れる
      ← ここが `token_hash` 方式の確認。**これが通らなければ方式が効いていない**
- [ ] 続けて2通目・3通目を送っても届く（手順4が効いているかの確認）

**リンクを押しても `/login` に戻ってしまう場合**、まず文面の `type=signup` を
`type=email` に変えて再送する。受け取り側は**両方を通す**ように書いてあるので、
コードは触らなくてよい。どちらが通ったかを、この作業記録に書き残すこと。

> 一度使ったリンクと期限切れのリンクは無効になり、`/login?error=auth_callback` に戻る。
> **これは正常な動作。** 再確認したいときは登録画面からもう一度進めば、同じメールが再送される。
