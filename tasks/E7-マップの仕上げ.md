## 何をするか

ステージ選択画面の細かい残りを2つ片付ける。

### ① 満点をとったステージを見て分かるようにする

いまマップ上のマークは3種類しかない。

- クリア済み
- 現在地
- 未開放

**80点以上（パーフェクト）を取ったステージも、55点でクリアしたステージも同じ見た目。**
せっかく高得点の帯域を作ってあるのに、マップに反映されていない。

### ② 見出しとノードの位置ずれを直す

章の見出しと、その下のステージの丸の位置が少しずれている。

---

## なぜ必要か

**①は「もう一度やる理由」になる。**
一度クリアすると先へ進めるので、戻ってくる動機がいまは無い。
「金色になっていないステージがある」と見えれば、復習する理由が生まれる。

②は単なる見た目の粗さだが、**マップは毎回見る画面**なので気になりやすい。

---

## ⚠️ オーナーに確認すること

> 満点のステージをどう見せますか。
>
> - **案A: 金色の縁取り**（デザイン案の想定）
> - 案B: マークを変える（星など）
> - 案C: 光る演出を付ける
>
> **考えどころ:** ここは「集めたくなる」かどうかを左右します。
> 目立ちすぎると、クリア済み（55点以上）のステージが見劣りして
> **「クリアしただけでは足りない」という印象**になりかねません。
> Ferret はネガティブな印象を避ける方針なので、
> **控えめな差**（案A）を勧めます。

## 作業記録

**2026-08-17 実施。** 触ったのは `components/stage/StageMap.tsx` と `app/stages/page.tsx` の2つだけ。

### ① 満点の表示 ── 案A（金色の縁取り）で実装

> **オーナー判断（2026-08-18）: 案A で確定。** 実装後に案A・案B（星マーク）・案C（発光）の
> 違いと懸念を提示したうえでの承諾。**案B・案C は見送り**なので蒸し返さないこと。

見せ方は**案A**にした。`ring-3 ring-[#d98a06] ring-offset-2` で、クリア済みの丸の外側に
金の輪をひと重足すだけ。**マークも大きさも色も変えていない。**

- 案Aを選んだ理由: 目立たせすぎると 55点でクリアしたステージが見劣りし、
  「クリアしただけでは足りない」という印象になる（ネガティブな印象を避ける方針に反する）
- 色は新しく作らず、**クリア済みの丸の下辺に既に使われている `#d98a06` を流用した。**
  「新しい色が増えた」ではなく「同じ金がもう一重ある」と読めるほうが控えめに収まる
- `ring-offset` でクリーム色の隙間を空けているので、輪が独立した縁として見える

**判定は `Stage.perfect` という独立した欄で持たせた。`status` の4つ目の値にはしていない。**
満点のステージはクリア済みでもあるため、4つ目の値にすると
`status === "cleared"` で書かれている判定（道の実線・ボタン文言・見た目）が
**すべて満点ノードを取りこぼす。**

基準は `lib/ai/compose.ts` の `PERFECT_THRESHOLD` を `app/stages/page.tsx` から読む。
画面に 80 を直接書いていない（注意書きのとおり）。

ポップオーバーには STAGE 番号の隣に「満点」の丸ピルを出す。

> **見せ方を変えたくなった場合、直すのは `StageMap.tsx` の `isPerfect` の分岐1箇所だけで済む。**

### ② 位置ずれ ── 原因は2つあった。両方直した

**憶測で定数をいじると 100問で崩れるので、ブラウザで実測してから直した。**
（モックと React 側の geometry は完全に一致していた。移植ミスではなく設計側の値の問題）

**(a) 節の高さが実データのタイトルに足りていなかった**

モックの `ROW_H = 145` は「try/catch の流れ」のような**短いタイトル前提**の値。
実データのタイトルは「スタックトレースを読む ─ ログから原因の行を特定する」のように
144px 幅で**3行に折り返す**ため、

- ラベルが次の行の丸に重なる
- 章の最後のノードが**節の下端を 20px はみ出す**（実測 `slackBelow: -20`）
- その結果、**章見出し（「ここから 第N章」）と直上のステージの間隔が 8px / 16px / 38px とバラバラ**になり、
  8px のときは見出しがラベルに貼り付いて見えていた

直し方:

| | |
|---|---|
| `ROW_H` | 145 → **180**（ノードの最大高 168 を収める） |
| ラベル | `h-19` で**高さを固定**し、`line-clamp-3` で3行に打ち切る。行数でノードの高さが動かないようにする |
| 節の高さ | `行数 × ROW_H + PAD_TOP` → **`(行数-1) × ROW_H + PAD_TOP + NODE_H`**。「最後のノードが収まる位置」で下端を決める |

実測で **章見出しの上の余白が全章 44px に揃った**（末尾が現在地の章だけ 36px。
現在地は丸が大きく 8px 持ち上げてあるぶんで、意図した差）。

**タイトルは切り詰めていない。** 3行までは全部出る。
`line-clamp-3` は4行以上になる将来のタイトルでレイアウトが壊れないための上限。
代わりに**マップは 100問で 16,760px → 20,092px（+20%）縦に長くなる。**
コンパクトさを優先するなら「マップ上は ─ の前だけ出す」という手があるが、
**表示する文字を勝手に削る判断はしていない。** 気になるならそこはオーナーの判断。

**(b) 起動直後に、章バナーがステージの丸を覆っていた**  ← タスク票の
「章の見出しの高さと、ステージの丸の開始位置がずれている」はこれだった

`scrollIntoView({ block: "center" })` は**バナーの高さを勘定に入れない**ため、
画面上端から数えた中央に現在地が来ていた。その結果、
**現在地の1つ上のノードがちょうど sticky バナー（16〜97px を占める）の裏に入り、
丸だけが隠れてラベルだけが浮く**状態が、/stages を開くたびの既定の見た目になっていた。

`scrollToCurrent()` を足して、**バナーの下の「実際に見えている範囲」の中央**に置くようにした。
「現在地へ」ボタンも同じ関数を通すので、押したときの着地点が起動時と揃う。

**ただし中央に置くだけでは足りなかった。** バナーの帯にどの丸が来るかは**画面の高さ次第**で、
実測すると 900px 高では 14.5px かかったままだった。**かかっていたら下へずらす**処理を足した。
`ROW_H`(180) ≥ バナー高(81) + 丸(76) + 余裕(8) = 165 が成り立つ限り、
帯にかかる丸は多くても1つなので、ずらして別の丸が新たにかかることはない。

**さらにその実装に穴があり、検証で見つけて直した。**
ページの端では狙った位置までスクロールできずブラウザ側で丸められるため、
**丸める前の値で判定していると、ずらしが効かない。**
これは**新規ユーザーの初回表示で必ず起きる**（現在地が STAGE 1 ＝ マップ最下部なので着地位置が末尾で丸められる）。
実測でも丸が 19.5〜76px 隠れていた。先に丸めてから判定するようにして解消した。

### 確認したこと（実測値）

**進行状況2種 × 画面4種の8通りで測った。**

| | |
|---|---|
| 満点の輪 | 8通りすべてで **100/92点のステージにだけ付く**（60/70/58点には付かない） |
| バナーに重なる丸 | **8通りすべて「なし」** |
| タイトルの打ち切り | **8通りすべて「なし」**（現データの最長は3行） |
| 章見出しの余白（箱基準） | 全章 44px（末尾が現在地の章のみ 36px） |
| 100問時 | 章定義14章に当てて算術で確認。`ROW_H(180) > NODE_H(168)`。全長 20,092px |
| テスト・ビルド | `npm test` 569 passed / 63 skipped、`npm run build` 通過 |

**「揃っている」の限界を正確に書いておく。** 上の 44px は**箱の下端基準**で、
**文字の最終行から見た余白は 37.9 / 45.9 / 65.9px の3種類**残っている。
ラベルの高さを固定した（3行ぶん確保）ため、**2行のタイトルだと箱の中に空きが出る**のが理由。

- 変更前: **8 / 16 / 38px**（しかも節から 20px はみ出していて、見出しがラベルに貼り付いていた）
- 変更後: **37.9 / 45.9 / 65.9px**（はみ出しは解消。最小でも 38px 空く）

ばらつきの幅は変わっていない（30px → 28px）。**直ったのは「貼り付き」と「はみ出し」で、
完全な等間隔にはなっていない。** 等間隔にするには節の高さを
「実際の文字の高さ」に合わせる必要があり、描画後の実測（ResizeObserver など）が要る。
章の境目は 1,000px 以上離れていて2つ同時に視界に入らないため、**そこまではやっていない。**
