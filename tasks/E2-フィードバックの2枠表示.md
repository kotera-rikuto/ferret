## 何をするか

採点のあとに出る文章を、**2つの枠に分けて表示する。**

AIは実はもともと2つに分けて書いている。

- **よかったところ**（読めている点）
- **つぎの一歩**（次にどこを見るとよいか）

ところが**保存するときに2つを1本の文章につなげてしまっている**ので、
画面で分けられない。

---

## なぜ必要か

デザイン案では2枠で作ってあり、そのほうが読みやすい。
「褒められている部分」と「次にやること」が視覚的に分かれる。

またこの2つは**別々に検査されている。** 禁止された言葉が片方に入ったとき、
その片方だけを差し替える作りになっている。つなげて保存すると、
**どちらが差し替わったのかも分からなくなる。**

---

## いまどうなっているか

`lib/ai/scorer.ts` のこの行で1本につなげている。

```ts
const text = [praise.text, next.text].filter(Boolean).join(" ");
```

そのあと `user_attempts` の `ai_feedback` という1つの欄に保存している。
**分けて保存していないので、後から復元できない。**

---

## ⚠️ オーナーに確認すること

> 保存の形を変える必要があります。2つのやり方があります。
>
> **案A: 欄を2つに増やす**
> いまの「AIからの文章」の欄に加えて、「よかったところ」「つぎの一歩」の欄を足します。
> - よい点: 分かりやすい。中身を検索したり集計したりしやすい
> - 悪い点: データベースの変更が1回必要
>
> **案B: 1つの欄にまとめて入れる（構造を持たせた形で）**
> いまの欄に、2つに分けられる形で入れます。
> - よい点: データベースの変更が要らない
> - 悪い点: **過去に保存した分は古い形のまま**なので、
>   画面で「古い形」と「新しい形」の両方を扱う必要が出ます
>
> **おすすめは案A**です。データベースの変更は15分程度で、
> 一方で「2つの形が混在する」状態は、この先ずっと画面の複雑さとして残るためです。
>
> あわせて、**過去の採点結果をどうしますか。**
> - **案1: 古いものは今までどおり1枠で表示**（おすすめ・作業が軽い）
> - 案2: 過去の分も分け直す（採点をやり直すことになるので費用がかかる）

---

## 手順（案Aの場合）

1. マイグレーションを追加
   - `user_attempts` に `ai_praise text` と `ai_next_focus text` を足す（**どちらもNULL可**）
   - 既存の `ai_feedback` は**消さない**（過去の分が入っている）
2. `supabase db push`
3. `lib/ai/scorer.ts` — つなげる前の2つを、それぞれ返すようにする
   - **つなげた文章も引き続き返すこと**（過去との互換のため）
4. `app/api/score/route.ts` — 3つとも保存する
5. `app/result/[id]/ResultView.tsx` — 2枠で表示する
   - **新しい欄が空のとき（過去の分）は、今までどおり1枠で表示すること**
   - 見た目は `design/result-desktop-light.html` に合わせる
6. `ideas/db仕様.md` に欄を追記
7. `npm test` と `npm run build`

### 決めたこと（2026-08-18 / オーナー判断）

| 論点 | 決定 | 理由 |
|---|---|---|
| 保存の形 | **案A（欄を2つ追加）** | 「古い形と新しい形が混在する」状態は、この先ずっと画面の複雑さとして残る |
| 過去の採点結果 | **分け直す。ただし再採点はしない** | 票は「1枠のまま」か「再採点」の2択だったが、実データを見たところ**保存済みの文章をそのまま2つへ戻せる**ことが分かったため、3つ目の案に変更して確認を取った。費用ゼロ・点数は1点も動かない |

**なぜ再採点をやめたか。** 同一回答でも点は揺れる（実測で24点動いた記録がある）。
点数を上書きすると、**レベル（XP）とマップのクリア状態が後から動く** ──
`lib/progress/level.ts` は問題ごとの最高点から毎回導出しているため。
目的は「2枠で表示すること」なので、点数を動かす必要がなかった。

### 実装

- `supabase/migrations/20260818224500_attempt_feedback_split.sql` — `user_attempts` に
  `ai_praise` / `ai_next_focus`（どちらも NULL 可）。**`supabase db push` 済み**
- `lib/ai/scorer.ts` — `resolveFeedback` が2つを保ったまま返すようにした（`joinFeedback` を追加）。
  つなげた文章も従来どおり返す。**採点の計算とプロンプトは1文字も触っていない。`grader_version` も上げていない**
- `app/api/score/route.ts` — 3つとも保存。**リプレイ経路でも2欄を複製する**（票に書かれていなかった箇所。
  ここが抜けると「同じ回答を送り直したら文章が1枠に戻る」という食い違いが出る）
- `app/result/[id]/page.tsx` / `ResultView.tsx` — 2欄を取得して2ブロックで表示。
  見出しのピルはモック（`design/result-desktop-light.html` の `.fb-tag`）に合わせた
- `ideas/db仕様.md` — 欄を追記

**空の枠は出さない。** 片方が空になるのは、禁止語で差し替えた先のテンプレート自体が
空の帯域（80点以上には「つぎの一歩」が無く、55点未満かつ `core=none` には「よかったところ」が無い）。
両方が空になる回だけ定型文へ落とし、その落とし先は**「つぎの一歩」に寄せた**（場所を指す文なので、
「よかったところ」の見出しに入れると内容と食い違う）。

### 過去データの復元

`supabase/backfill/20260818224500_split_feedback.mjs`（**AIを呼ばない・点数を触らない・何度でも流せる**）。
既定は下見だけで、書き込むには `--apply` を付ける。

**なぜ機械的に戻せるか。** つないでいたのは `join(" ")` で、**日本語の文の切れ目に半角スペースは入らない**
（実データでも「〜です。次に、〜」と続いている）。したがって「。」＋半角スペースの並びは境目にだけ現れる。
実データで境目が2つ以上ある行は0件だった。境目が無い行は片方の枠が空だった回で、
空になり方は `templatePraise` / `templateNextFocus` から上記の2通りに限られるため、点数と `core` の判定から復元できる。

| 実測（2026-08-18・実行時点で42件） | |
|---|---|
| 復元した行 | **40件** |
| 1枠のまま残した行 | **2件** — 文章を2項目に分ける前（2026-08-16 の変更より前）に採点した行。元から2つになっていないので触っていない。どちらも `problem=5` の 63点で、**最新ではないため画面には出ない** |
| 費用 | **¥0** |

対象はすべて開発用アカウント（`dev@ferret.test`）の動作確認データで、**実ユーザーの記録は1件も無い。**
