# C8. 検索で見つかるようにする（技術的 SEO）

**種別:** 実装（小） + 管理画面の設定
**規模:** 小
**前提として終わっていること:** **C5（本番デプロイ）** ── 本番URLが無いと何も申告できない

> ### ⚠️ これより先に済ませること
> **OpenAI の使用量上限を設定してから着手する**（`tasks/C5-本番デプロイ.md` の「残っていること」）。
> **D-1（プラン別の採点上限）が未実装なので、登録した人は無制限に AI 採点を回せて原価はこちら持ち。**
> 検索に載れば人が来るので、**蛇口を締める前に流入を増やすのは順番が逆。**

**先に読むもの**
- `tasks/C5-本番デプロイ.md` の作業記録（公開範囲の判断と、DNS を触るときの注意）

---

## 何をするか

**公開したのに検索しても出てこない**状態を直す。

2026-08-22 に `https://ferretcode.com` を公開したが、「フェレット プログラミング」で検索しても出てこない。
理由は4つあり、**このタスクで直せるのは上の2つだけ。**

| | 理由 | このタスクで直る |
|---|---|---|
| 1 | まだ検索エンジンの索引に登録されていない（公開直後） | ✅ 登録を申告できる |
| 2 | **見つけてもらう手がかりが1つも無い** ── `sitemap` も `robots` も無く、外部リンクもゼロ | ✅ |
| 3 | 検索に出るページが5枚しかない（問題100問はログインの向こう） | ❌ 事業判断（下記） |
| 4 | 「フェレット」は動物と同名の先客（`ferret-plus.com`）が強い | ❌ 時間の問題 |

**このタスクは「索引に載る資格を得る」までで、「上位に出る」ことは約束しない。**
順位を決めるのは中身と外部からの評価で、そちらは別の話（→ 下の「このタスクの外」）。

---

## なぜ必要か

検索結果は「検索エンジンが持っている索引」を引いているだけで、
**索引に載っていないページは、どんな語で検索しても絶対に出ない。**

検索エンジンはリンクを辿って新しいページを見つける。`ferretcode.com` は
**今日できた新規ドメインで、どこからも1本もリンクされていない。**
つまり向こう側から見ると、このサイトの存在を知る材料が何も無い。
`sitemap.xml` と Search Console への登録は、その「材料」を自分から渡す仕組み。

---

## 手順

### 1. `app/robots.ts` を作る

```
User-agent: *
Allow: /
Disallow: /stages, /problems, /result, /review, /settings, /api
Sitemap: https://ferretcode.com/sitemap.xml
```

- **`Disallow` に認証が要るパスを列挙する。** `proxy.ts` の matcher と同じ範囲。
  どうせログイン画面に飛ばされるが、**列挙しないと巡回の手間をそこで使われる**うえ、
  「ログインへのリダイレクト」が索引に載ることがある
- ⚠️ **`Disallow: /` にしないこと。** それは検索避け（noindex）で、
  **C5 でオーナーが「検索に出したい」と判断済み**（`tasks/C5` の作業記録）

### 2. `app/sitemap.ts` を作る

載せるのは**ログイン不要の4枚だけ** ── `/` `/terms` `/privacy`、
それと必要なら `/register`。

- ⚠️ **`/login` は載せない。** 検索から来た人の入口は `/`（はじめる導線がある）
- ⚠️ **認証が要るページを1つも載せないこと。** URL の一覧を外に配ることになる

### 3. メタデータを足す（`app/layout.tsx`）

いまは `title` と `description` の2行だけ。足すもの:

| 項目 | 中身 |
|---|---|
| `metadataBase` | `NEXT_PUBLIC_APP_URL` から作る。**ハードコードしない** |
| `openGraph` | SNS に貼ったときのカード（`title` / `description` / `url` / `siteName` / `locale: "ja_JP"`） |
| `alternates.canonical` | 同じ内容が複数のURLで見えることを防ぐ |
| `title.template` | 画面ごとのタイトルを `〜 | Ferret` の形にする |

- ⚠️ **`NEXT_PUBLIC_APP_URL` は Production だけに入っている**（C5 の判断）。
  プレビューでは未設定なので、`metadataBase` は
  **未設定なら組み立てない**か、リクエスト元から作る形にする。
  ここで固定値を書くと、プレビューのページが本番URLを名乗る
- タイトル画面の本文には「フェレット」「コードリーディング特化プログラミング学習サイト」と
  書いてあるのに、メタデータ側で宣言していない。**素材はあるので、それを使う**

### 4. OG 画像（任意）

`app/opengraph-image.tsx` でマスコットを使ったカード画像を作れる。
**無くても検索には載る**ので、急がなければ後回しでよい。
作るなら **`components/ui/Mascot.tsx` が唯一の入口という決まりを崩さないこと**（`CLAUDE.md`）。

### 5. Google Search Console に登録する（管理画面）

1. Search Console でプロパティを追加（**ドメイン単位**を選ぶ）
2. 所有確認のため **apex に TXT レコードを1行**追加（ムームーDNS のカスタム設定）
3. `sitemap.xml` を送信
4. **URL 検査 → インデックス登録をリクエスト**（これが一番早い経路）

> ### ⚠️ DNS を触るときの注意（C5 と同じ）
>
> ムームーDNS には**すでに5行**入っている ── Resend の4行
> （`send` の MX と TXT / `resend._domainkey` の TXT / `_dmarc` の TXT）と、
> C5 で足した apex の `A 76.76.21.21`。
> **1行も消さないこと。** 消すとメールが止まり、しかも**止まったことに気づけない。**
>
> **ネームサーバーを Vercel に変えてはいけない**（上の5行が全部消える）。
> Search Console の所有確認は apex の TXT で、**apex に TXT はまだ無いので純粋な足し算**
> （2026-08-22 に `dig` で確認済み）。

### 6. 費用

**全部 ¥0。** Search Console は無料、残りはコードを書くだけ。
検索に載せる作業で課金される仕組みは（広告を出す以外に）無い。

## ⚠️ オーナーに確認すること

> **`/register` を検索に載せますか。**
> 載せると「登録画面」が直接検索結果に出ます。入口としては `/` のほうが説明があるので、
> **載せない**ほうが素直だと思いますが、どちらでも動きます。

## 触る場所

| 場所 | 何をするか |
|---|---|
| `app/robots.ts` | 新規。巡回してよい範囲を宣言する |
| `app/sitemap.ts` | 新規。ログイン不要のページを申告する |
| `app/layout.tsx` | `metadata` に `metadataBase` / `openGraph` / `canonical` を足す |
| `app/opengraph-image.tsx` | 任意。SNS 用のカード画像 |
| Google Search Console | プロパティ追加・sitemap 送信・インデックス登録の依頼 |
| ムームーDNS | 所有確認の TXT を**1行足すだけ**（既存5行は触らない） |

## 終わったと言える条件

- [ ] `https://ferretcode.com/robots.txt` と `/sitemap.xml` が本番で返る
- [ ] `sitemap.xml` に**認証が要るURLが1つも入っていない**
- [ ] Search Console で所有確認が済み、sitemap を受け付けている
- [ ] `site:ferretcode.com` で少なくともトップページが出る（**数日〜数週間かかる**）
- [ ] ムームーDNS の既存5行が無事（`dig` で確認）
- [ ] `npm test` と `npm run build`

## このタスクの外（順位を上げたいなら別の判断が要る）

**技術的 SEO をやり切っても、索引に載るのは実質「トップページ1枚」。**
問題100問は `proxy.ts` が守っているのでクローラーに見えない。
「フェレット プログラミング」で検索した人が読んで満足するページは、いま存在しない。

順位を狙うなら**公開側にコンテンツを置く**ことになり、これは実装ではなく事業判断:

- サンプル問題を数問、ログイン不要で読める形にする（そのまま体験導線にもなる）
- 「コードリーディング」について書いた記事を置く

**どこまで無料で見せるかは料金プラン（`ideas/仕様書.md` §3）と直結する**ので、
A2 が終わって次の一手を決める段で議論すること。**このタスクでは扱わない。**
