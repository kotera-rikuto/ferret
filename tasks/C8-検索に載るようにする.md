## 何をするか

**公開したのに検索しても出てこない**状態を直す。

2026-08-22 に `https://ferretcode.com` を公開したが、「フェレット プログラミング」で検索しても出てこない。
理由は4つあり、**このタスクで直せるのは上の2つだけ。**

| | 理由 | このタスクで直る |
|---|---|---|
| 1 | まだ検索エンジンの索引に登録されていない（公開直後） | ✅ 登録を申告できる |
| 2 | **見つけてもらう手がかりが1つも無い** ── `sitemap` も `robots` も無く、外部リンクもゼロ | ✅ |
| 3 | 検索に出るページが5枚しかない（問題100問はログインの向こう） | ❌ 事業判断（下記） |
| 4 | 「フェレット」は動物と同名の先客（`ferret-plus.com`）が強い | ❌ 時間の問題 |

**このタスクは「索引に載る資格を得る」までで、「上位に出る」ことは約束しない。**
順位を決めるのは中身と外部からの評価で、そちらは別の話（→ 下の「このタスクの外」）。

---

## なぜ必要か

検索結果は「検索エンジンが持っている索引」を引いているだけで、
**索引に載っていないページは、どんな語で検索しても絶対に出ない。**

検索エンジンはリンクを辿って新しいページを見つける。`ferretcode.com` は
**今日できた新規ドメインで、どこからも1本もリンクされていない。**
つまり向こう側から見ると、このサイトの存在を知る材料が何も無い。
`sitemap.xml` と Search Console への登録は、その「材料」を自分から渡す仕組み。

## 手順

### 1. `app/robots.ts` を作る

```
User-agent: *
Allow: /
Disallow: /stages, /problems, /result, /review, /settings, /api
Sitemap: https://ferretcode.com/sitemap.xml
```

- **`Disallow` に認証が要るパスを列挙する。** `proxy.ts` の matcher と同じ範囲。
  どうせログイン画面に飛ばされるが、**列挙しないと巡回の手間をそこで使われる**うえ、
  「ログインへのリダイレクト」が索引に載ることがある
- ⚠️ **`Disallow: /` にしないこと。** それは検索避け（noindex）で、
  **C5 でオーナーが「検索に出したい」と判断済み**（`tasks/C5` の作業記録）

### 2. `app/sitemap.ts` を作る

載せるのは**ログイン不要の4枚だけ** ── `/` `/terms` `/privacy`、
それと必要なら `/register`。

- ⚠️ **`/login` は載せない。** 検索から来た人の入口は `/`（はじめる導線がある）
- ⚠️ **認証が要るページを1つも載せないこと。** URL の一覧を外に配ることになる

### 3. メタデータを足す（`app/layout.tsx`）

いまは `title` と `description` の2行だけ。足すもの:

| 項目 | 中身 |
|---|---|
| `metadataBase` | `NEXT_PUBLIC_APP_URL` から作る。**ハードコードしない** |
| `openGraph` | SNS に貼ったときのカード（`title` / `description` / `url` / `siteName` / `locale: "ja_JP"`） |
| `alternates.canonical` | 同じ内容が複数のURLで見えることを防ぐ |
| `title.template` | 画面ごとのタイトルを `〜 | Ferret` の形にする |

- ⚠️ **`NEXT_PUBLIC_APP_URL` は Production だけに入っている**（C5 の判断）。
  プレビューでは未設定なので、`metadataBase` は
  **未設定なら組み立てない**か、リクエスト元から作る形にする。
  ここで固定値を書くと、プレビューのページが本番URLを名乗る
- タイトル画面の本文には「フェレット」「コードリーディング特化プログラミング学習サイト」と
  書いてあるのに、メタデータ側で宣言していない。**素材はあるので、それを使う**

### 4. OG 画像（任意）

`app/opengraph-image.tsx` でマスコットを使ったカード画像を作れる。
**無くても検索には載る**ので、急がなければ後回しでよい。
作るなら **`components/ui/Mascot.tsx` が唯一の入口という決まりを崩さないこと**（`CLAUDE.md`）。

### 5. Google Search Console に登録する（管理画面）

1. Search Console でプロパティを追加（**ドメイン単位**を選ぶ）
2. 所有確認のため **apex に TXT レコードを1行**追加（ムームーDNS のカスタム設定）
3. `sitemap.xml` を送信
4. **URL 検査 → インデックス登録をリクエスト**（これが一番早い経路）

> ### ⚠️ DNS を触るときの注意（C5 と同じ）
>
> ムームーDNS には**すでに5行**入っている ── Resend の4行
> （`send` の MX と TXT / `resend._domainkey` の TXT / `_dmarc` の TXT）と、
> C5 で足した apex の `A 76.76.21.21`。
> **1行も消さないこと。** 消すとメールが止まり、しかも**止まったことに気づけない。**
>
> **ネームサーバーを Vercel に変えてはいけない**（上の5行が全部消える）。
> Search Console の所有確認は apex の TXT で、**apex に TXT はまだ無いので純粋な足し算**
> （2026-08-22 に `dig` で確認済み）。

#### canonical を `app/layout.tsx` に置かなかった理由（票の手順3からの変更）

**票のとおり `layout.tsx` に `alternates.canonical` を1行書くと、`/terms` と `/privacy` が
「正しいURLはトップページ」と申告する。** Next.js のメタ情報は「下の階層が書いていない項目を
そのまま受け継ぐ」ので、canonical も受け継がれる ── 法務2枚がトップの複製として扱われ、
索引から外れうる（`node_modules/next/dist/docs` の generate-metadata.md「Inheriting fields」）。

canonical はページごとに違う値でなければ意味がないので、
入口を `publicPageMetadata`（`lib/seo/site.ts`）1本にして、各ページから渡す形にした。
同じ理由で `og:url` も layout には置いていない。検査は U-838。

#### `/login` `/register` に `index: false` を足した理由

**sitemap から外すだけでは「検索結果に出ない」にならない。** sitemap は
「見に来てほしい一覧」であって「これ以外を見るな」ではなく、**トップページから両方に
リンクが張ってある**ので、検索エンジンはリンクを辿って普通に見つける。
オーナーに説明した内容（「`/register` が検索結果に単独で出ることはありません」）を
実際にそうするため、ページ側で `index: false` / `follow: true` を宣言した。

`robots.txt` で塞ぐのは**逆効果**なので、この2枚は意図的に `Allow` のまま残してある ──
塞ぐと中身を読めなくなるだけで、リンクされていれば**説明文の無い URL だけの結果**が出る。
「読ませたうえで、載せないでくれと伝える」のが正しい形。検査は U-843・U-844。

なお2枚とも `"use client"` で `metadata` を書き出せないため、
`app/login/layout.tsx` / `app/register/layout.tsx`（宣言だけを持つ層）を足している。

### 詰まった点・気づき

- **`NEXT_PUBLIC_APP_URL` が未設定のときの扱いが、票の想定より重い。**
  Next.js 16 は **`metadataBase` の無い相対パスをビルドで弾く**（警告ではなくエラー）。
  票の「未設定なら組み立てない」をそのまま実装しないと、**プレビュー配信のビルドが丸ごと失敗する。**
  `NEXT_PUBLIC_APP_URL` はローカルの `.env.local` でも空なので、`npm run build` の時点で踏む
- **`robots.txt` は基点が無くても全部出す形にした。** 「本番URLが分からないなら全面禁止」は
  一見安全だが、`NEXT_PUBLIC_APP_URL` の設定漏れがそのまま**サイト全体の検索避け**になる
  （C5 のオーナー判断と真逆・しかも画面は何も変わらない）。`Allow` / `Disallow` は相対パスなので
  基点と無関係に正しく、分岐させる理由が最初から無い。基点が要るのは `Sitemap:` の1行だけ
- **`proxy.ts` の `config.matcher` は共有できない。** Next.js の制約でリテラルの配列でなければならず、
  `CRAWL_DISALLOW` から組み立てられない。二重管理が避けられないので、
  **片方に足してもう片方を忘れた瞬間に落ちる**検査を置いた（U-830・U-836。
  `proxy.ts` を import せずソースを文字列として読む ── import すると Supabase の組み立てまで引き込むため）
- **E-450（E2E）の期待値が変わった。** トップの `<title>` が `"Ferret"` から
  検索結果の見出し（`SITE_TITLE`）になったため、定数を照合する形に直した。
  `/login` のタイトルが二重（「ログイン | Ferret | Ferret」）にならないことを見る E-450b を足してある
- **`tests/**/テストケース.md` は `.gitignore` 済み**で、リポジトリには入らない。
  §18（U-830〜U-844）と E-450b の追記は**本体の作業ツリー側のファイルに直接書いた**
- `dig` がこの環境から引けない（DNS が通らない）。**DNS の現状確認はオーナー側で実施が必要**

### 1. インデックス登録をリクエストする ── ✅ **完了（2026-08-22 21:17）**

**押した。「URL を優先クロール キューに追加しました」。**

| 項目 | 表示 | 読み方 |
|---|---|---|
| インデックス | **クロール済み - インデックス未登録** | **Googlebot はもう来ている**（sitemap 送信の約2時間後）。そのうえで載せる判断を保留している |

**「クロール済み - インデックス未登録」はこちら側の不備ではない。**

## 参考: 公開直後にやったこと（記録）

### 1. 本番に反映する

`main` に入れば Vercel が自動で公開する。反映後、この2つが返ることを確認する:

```bash
curl https://ferretcode.com/robots.txt     # Sitemap: の行まで出ること
curl https://ferretcode.com/sitemap.xml    # URL が3件入っていること
```

> ⚠️ **`Sitemap:` の行が無く、`sitemap.xml` が空で返ってきたら、Vercel の Production に
> `NEXT_PUBLIC_APP_URL` が入っていない。** ビルドは成功するので、**見に行かないと気づけない。**
> C5 で入れた（`https://ferretcode.com`）ことになっているが、上の curl が実質の確認になる。

### 2. Google Search Console に登録する

1. Search Console でプロパティを追加 ── **「ドメイン」**のほうを選ぶ（URL プレフィックスではない）
2. 表示された **TXT レコードを apex（`ferretcode.com`）に1行足す**（ムームーDNS のカスタム設定）
3. 所有確認 → `sitemap.xml` を送信
4. **URL 検査 → インデックス登録をリクエスト。これが一番早い経路**

> ### ⚠️ DNS を触るときの注意（C5 と同じ）
>
> ムームーDNS には**すでに5行**入っている ── Resend の4行（`send` の MX と TXT /
> `resend._domainkey` の TXT / `_dmarc` の TXT）と、C5 で足した apex の `A 76.76.21.21`。
> **1行も消さないこと。** 消すとメールが止まり、しかも**止まったことに気づけない。**
> **ネームサーバーを Vercel に変えてはいけない**（上の5行が全部消える）。
>
> 作業前後に `dig` で5行が無事なことを確認する（**この環境からは DNS が引けなかったので未確認**）:
> ```bash
> dig +short ferretcode.com A            # 76.76.21.21
> dig +short send.ferretcode.com MX
> dig +short send.ferretcode.com TXT
> dig +short resend._domainkey.ferretcode.com TXT
> dig +short _dmarc.ferretcode.com TXT
> dig +short ferretcode.com TXT          # 追加した Search Console の1行
> ```

### 3. 待つ

`site:ferretcode.com` でトップページが出るまで**数日〜数週間**。
インデックス登録をリクエストすれば早まるが、**即日ではない。**
**（実績: 2026-08-22 にリクエスト → 08-24 に登録。2日だった。）**
